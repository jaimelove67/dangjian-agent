## 1 引言与总体说明

### 1.1 项目背景

高校党建工作存在知识分散、流程繁琐、重复填报、留痕合规性要求高等问题。本项目建设一个面向高校党建工作的智能体产品，作为党建工作的辅助工具，为党务工作者提供知识问答、材料整理、流程指引、数据分析等能力，**AI 仅提供辅助，业务结论与关键流转必须人工审核**。

### 1.2 产品定位与目标

- 建设独立党建知识问答系统，**不依赖扣子等第三方智能体平台**，基于自有技术栈实现。
- 采用 **"公共能力 + 学校/院系个性化配置"** 的产品模式。
- 支持多学校、多院系、多支部的租户化部署与私有化部署。
- 最终形成可面向不同学校和院系交付的产品，而非单一项目定制系统。

### 1.3 产品范围

| 阶段 | 范围 | 说明 |
| --- | --- | --- |
| 本期（第一阶段） | 知识库、知识问答、来源引用、基础后台管理 | 优先落地，经湘潭大学老师试用确认业务流程 |
| 第二阶段 | 党员发展、组织生活 | 逐步扩展业务模块 |
| 第三阶段 | 中心组学习、党建考核、多租户产品化 | 产品化与私有化部署 |

### 1.4 术语与定义

| 术语 | 说明 |
| --- | --- |
| 智能体（Agent） | 具备感知、规划、调用工具与生成能力的程序；本项目以工作流为核心形态 |
| 工作流（Workflow） | 由 LangGraph 编排的、有状态的一连串节点执行过程；一条工作流只完成一个任务 |
| RAG / 知识问答 | 检索增强生成：先检索权威材料，再基于材料生成回答 |
| Embedding / 向量化 | 将文本转为向量用于语义检索 |
| Rerank / 重排序 | 对初检结果按相关性重新排序 |
| pgvector | PostgreSQL 向量检索扩展 |
| 租户（Tenant） | 独立数据隔离与权限边界，本项目对应"学校"级别 |
| 公共知识库 | 面向全校（及平台）开放的标准党建知识库 |
| 个性化知识库 | 学校、院系、支部自行维护的非公开知识库 |

## 2 总体技术路线

### 2.1 技术栈

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 智能体/工作流编排 | **LangGraph** | 有状态工作流编排。**注意：LangGraph 不是向量数据库，也不是完整后端框架**，需与下列组件配合 |
| 后端 | Python + **FastAPI** | REST API、鉴权、任务调度、审计 |
| 前端 | Vue 或 React | 管理后台与业务页面 |
| 大模型 | 通义千问、或可私有化部署的开源模型 | 按数据敏感度选择公网/私有模型 |
| Embedding | 通义千问 Embedding 或 BGE 系列 | 文本向量化 |
| 重排序 | BGE Reranker | 检索结果重排 |
| 业务数据库 | PostgreSQL | 业务数据、知识元数据 |
| 向量数据库 | PostgreSQL + pgvector（原型及首个正式版本） → Qdrant（规模/并发提升后） → Milvus（告评估，亿级向量） | 分级演进 |
| 文件存储 | MinIO 或学校内部对象存储 | 源文件、原始材料 |
| 文档解析 | 按文件类型选用 PDF / Word / Excel / OCR 等解析工具 | 上传文件解析入库 |

### 2.2 知识问答基本流程

```
文件上传 → 文档解析 → 文本切分 → 向量化 → 向量库检索
        → 重排序 → 大模型回答 → 引用来源核验 → 结果展示
```

### 2.3 架构图（逻辑视图）

```
┌──────────────────────────────────────────────┐
│ 前端（Vue / React）：工作台、知识库、问答、管理 │
└─────────────────────┬────────────────────────┘
                      │ HTTPS API
┌─────────────────────▼────────────────────────┐
│ 后端 FastAPI：鉴权 / 权限 / API / 审计 / 任务    │
│ ┌──────────────────────────────────────────┐ │
│ │ LangGraph 工作流引擎（单一任务工作流编排）   │ │
│ │ 文档入库｜知识问答｜引用核验｜敏感检查｜…     │ │
│ └──────────────────────────────────────────┘ │
└──────┬──────────┬──────────┬──────────┬───────┘
       │          │          │          │
   PostgreSQL   pgvector/    MinIO/    LLM+Embedding
   (业务数据)    Qdrant/    对象存储    +Rerank
                Milvus       (源文件)   (公网/私有)
```

### 2.4 关键澄清

- LangGraph 只负责**智能体与有状态工作流编排**。
- 系统仍需结合 **FastAPI、PostgreSQL、向量数据库、文档解析工具、对象存储、前端**共同实现完整功能。

## 3 工作流设计原则

### 3.1 一条工作流只完成一个任务

- 每条工作流必须对应一个**明确、可独立验收**的业务任务，禁止在同一条工作流中混合多个业务目标。
- 一条工作流内可以包含权限校验、数据检索、重排序、内容生成、人工审核、异常重试、审计记录等多个节点，但所有节点必须共同服务于**同一个最终任务**。
- 复合业务需求应拆分成多个独立任务，由不同工作流分别执行。

### 3.2 工作流与业务模块解耦

- 每条工作流具有独立的输入、输出、状态和权限要求。
- 单个工作流失败不影响其他工作流正常执行。
- 每条工作流支持独立测试、版本升级、日志记录和审计。
- 涉及敏感数据或业务结论的工作流必须设置**人工审核节点**。
- 工作流输出仅作为辅助材料时，必须**明确标注**，不得替代党组织决策。

### 3.3 工作流清单（建议拆分）

| 编号 | 工作流 | 所属业务 | 阶段 | 是否含人工审核 |
| --- | --- | --- | --- | --- |
| WF-01 | 文档解析入库工作流 | 知识库 | P0 | 否 |
| WF-02 | 党建知识问答工作流 | 知识问答 | P0 | 否 |
| WF-03 | 引用来源核验工作流 | 知识问答 | P0~P1（可后拆） | 否 |
| WF-04 | 敏感信息检查工作流 | 公共/知识问答 | P0~P1（可后拆） | 否 |
| WF-05 | 党员发展材料完整性检查工作流 | 党员发展 | P1 | 否 |
| WF-06 | 党员发展节点提醒工作流 | 党员发展 | P1 | 否 |
| WF-07 | 选优辅助分析工作流 | 党员发展 | P1 | **是** |
| WF-08 | 会议纪要生成工作流 | 组织生活 | P1 | **是** |
| WF-09 | 会议任务提取工作流 | 组织生活 | P1 | **是** |
| WF-10 | 中心组学习材料推荐工作流 | 中心组学习 | P2 | 否 |
| WF-11 | 党建考核材料缺项检查工作流 | 党建考核 | P2 | 否 |
| WF-12 | 年度党建计划生成工作流 | 党建考核 | P2 | **是** |

> 阶段说明：P0 = 第一阶段 MVP；P1 = 第二阶段；P2 = 第三阶段（详见第 10 章）。

### 3.4 工作流衔接机制

- 工作流之间通过**标准化的输入输出、任务状态、业务事件**进行衔接。
- 不允许工作流之间直接耦合实现细节，只允许通过标准化接口触发或消费结果。

## 4 用户角色与权限模型

### 4.1 角色

| 角色 | 数据范围 | 主要能力 |
| --- | --- | --- |
| 系统管理员 | 平台 | 开户、租户配置、系统治理、审计查看 |
| 学校管理员 | 学校（含院系/支部） | 全校知识库与业务管理、指标配置、归档确认 |
| 院系管理员 | 院系（含支部） | 本院系知识库与业务管理 |
| 支部书记 | 支部 | 支部名册、会议、材料、阶段流转 |
| 组织员 | 支部 | 同支部书记范围 |
| 普通党员 | 本人 | 本人档案、本人材料、制度问答 |
| 申请人 | 本人 | 仅公开制度问答 |

### 4.2 数据范围与权限要求

- 数据范围按 **本人 < 支部 < 院系 < 学校 < 平台** 逐级包含。
- 按学校、院系、支部输出范围分级设置知识库与业务数据访问权限（FR-SYS-03）。
- 审核类操作强制由"另一位组织人员"完成（会议纪要、学习纪要、考核审核等）。

### 4.3 多租户隔离

- 建立多租户数据隔离机制，防止跨学校、跨院系越权访问。
- 租户层级 `平台→学校→院系→支部` 与组织树一一对应。
- 平台视角账号与学校业务数据隔离。

> 需求编号规则：`FR-<模块>-<序号>`。优先级：P0（第一阶段 MVP）、P1（第二阶段）、P2（第三阶段）。

### 5.1 党建知识库

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-KB-01 | 建设统一的**公共党建知识库**：汇集政策法规、制度文件、标准流程和常见问题 | P0 | 公共库可由学校管理员维护，普通用户可检索 |
| FR-KB-02 | 支持学校、院系、支部建立**个性化知识库** | P0 | 各级可各自建库/维护，权限按 4.2 控制 |
| FR-KB-03 | 支持 **PDF、Word、Excel、图片** 等文件上传与解析（含 OCR） | P0 | 可上传并完成解析，解析失败有明确提示 |
| FR-KB-04 | 支持知识**分类、标签、版本、生效时间、失效时间**管理 | P0 | 知识条目可打标签并生效/失效 |
| FR-KB-05 | 支持公共 / 学校 / 院系 / 支部知识库**分级管理** | P0 | 各级数据互不可越权访问 |
| FR-KB-06 | 支持文档**更新、停用、删除和重新向量化** | P0 | 更新后重新切分向量化，旧版本可追溯 |
| FR-KB-07 | 支持**语义检索、关键词检索、混合检索和结果重排序** | P0 | 检索策略可配置，重排生效 |
| FR-KB-08 | 支持**引用溯源**：展示文件名称、章节、页码或原文片段 | P0 | 回答中的每一条引用可追溯到原文片段 |
| FR-KB-09 | 展示材料**依据、文件来源、发布时间和适用范围** | P0 | 引用条目含来源元数据 |
| FR-KB-10 | 对**过期、冲突或依据不足**的政策内容进行提示 | P0 | 命中过期文档给出风险提示并降权 |
| FR-KB-11 | 按学校、院系、支部和用户角色控制知识库访问权限 | P0 | 越权访问返回拒绝 |

### 5.2 党建知识问答助手

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-QA-01 | 验证用户身份和知识库访问权限 | P0 | 未登录/无权限时拒绝问答 |
| FR-QA-02 | 识别问题类型及检索范围 | P0 | 根据问题自动确定检索的知识库范围 |
| FR-QA-03 | 分别检索公共、学校、院系或支部知识库 | P0 | 按权限合并多库检索结果 |
| FR-QA-04 | 对检索结果进行重排序 | P0 | 排序结果随相关性变化 |
| FR-QA-05 | 根据**有效材料**生成回答 | P0 | 不得引用失效/越权文档 |
| FR-QA-06 | 核验回答与引用材料的一致性 | P0 | 回答与引用片段内容一致，无编造 |
| FR-QA-07 | 检查敏感信息和越权内容并提示风险 | P0 | 命中敏感规则时给出风险提示/拦截 |
| FR-QA-08 | 展示回答、引用来源和风险提示 | P0 | 展示三项内容，引用可点击溯源 |
| FR-QA-09 | 保存问答记录和操作日志 | P0 | 每次问答可审计追溯 |
| FR-QA-10 | **无依据时拒绝编造**，明确告知"无依据" | P0 | 库中无相关内容时不得臆造 |
| FR-QA-11 | 回答时明确 AI 输出仅为辅助材料（如需） | P1 | 标注"辅助参考，以正式文件为准" |

**知识问答主流程（对应用户视角）**：

```
1 验证用户身份和知识库访问权限
2 识别问题类型及检索范围
3 分别检索公共/学校/院系/支部知识库
4 对检索结果进行重排序
5 根据有效材料生成回答
6 核验回答与引用材料的一致性
7 检查敏感信息和越权内容
8 展示回答、引用来源和风险提示
9 保存问答记录和操作日志
```

## 6 核心工作流定义

### 6.1 WF-01 文档入库工作流（P0）

| 项目 | 定义 |
| --- | --- |
| 任务 | 将上传文件解析、切分、向量化并入库 |
| 输入 | 源文件（PDF/Word/Excel/图片）、目标知识库、分类/标签/有效期限等元数据 |
| 节点 | 文件校验 → 权限校验 → 格式识别 → 文档解析（含 OCR） → 文本切分 → 向量化（Embedding）→ 写入向量库与元数据表 → 状态更新与审计 |
| 输出 | 入库成功的知识条目/片段及其向量、文档状态、审计记录 |
| 状态 | 待处理 / 解析中 / 切分中 / 向量化中 / 成功 / 失败（可重试） |
| 说明 | 只完成"入库"单一任务；解析失败支持重试，不阻塞其他工作流 |

### 6.2 WF-02 知识问答工作流（P0）

| 项目 | 定义 |
| --- | --- |
| 任务 | 完成一次基于知识库的知识问答 |
| 输入 | 用户问题、用户身份与知识库权限范围、检索配置 |
| 节点 | 身份校验 → 权限校验 → 问题类型/检索范围识别 → 多库检索 → 重排序 → 材料有效性过滤（过期/冲突降权） → 答案生成 → 引用核验 → 敏感信息检查 → 风险提示与结果组装 → 记录问答日志 |
| 输出 | 回答正文、引用来源清单（文件名/章节/页码/片段）、风险提示、问答记录 |
| 状态 | 成功 / 无依据（拒绝编造）/ 无权限 / 敏感拦截 / 失败（可重试） |
| 说明 | 只完成"一次知识问答"的单一任务 |

### 6.3 后续可独立拆分的衔接工作流

- **WF-03 引用来源核验工作流**：对生成的回答与引用材料做一致性核验，通过标准化接口被问答工作流调用。
- **WF-04 敏感信息检查工作流**：对文本内容做敏感信息与越权内容检查，通过标准化接口被问答、入库等工作流调用。
- WF-05 ~ WF-12 详见 3.3 工作流清单。

> MVP 阶段至少包含 **WF-01 文档入库** 与 **WF-02 知识问答** 两条相互独立的核心工作流；引用核验、敏感检查后续拆分，通过标准化输入输出衔接，不阻塞 MVP 上线。

| 编号 | 需求 | 优先级 | 验收要点 |

| SEC-10 | 涉及评分、选优、党员发展结论时**保留评价依据，禁止完全依赖模型自动决策** | P1 | 辅助分析输出强制标注并保留依据 |
| SEC-11 | 对**模型提示词、知识库版本和工作流版本**进行留痕 | P1 | 版本信息可查、可追溯 |
| SEC-12 | 上线前由学校组织部门、信息化部门、保密管理部门**共同审核** | P1 | 审核意见进入发布清单 |

### 7.1 模型出网安全机制

- 大模型调用受 **出网白名单** 与 **数据分级闸门** 控制。
- 仅"公开/获准内部"内容允许接入公网模型；敏感内容调用前拦截，涉密内容拒绝 AI 处理。
- 敏感数据出网行为全部写审计日志。

## 9 数据与文件需求

### 9.1 知识库数据模型（要点）

- 知识库：`公共 / 学校 / 院系 / 支部` 四级，绑定租户与组织。
- 知识条目：标题、正文、分类、标签、版本、生效时间、失效时间、来源（文件/章节/页码）、上传者、状态。
- 片段/向量：源自文档切分，记录所属文档、页码/位置、向量数据、Embedding 模型版本。
- 问答记录：问题、回答、引用清单、风险提示、耗时、状态、关联用户与知识库范围。

### 9.2 文件存储

- 源文件存放 MinIO 或学校内部对象存储，数据库存元数据。
- 文件与备份加密（SEC-06）。

### 9.3 数据边界

- 公共知识库内容可入公共检索；学校/院系/支部私有内容仅在对应权限范围检索，**默认不进公网模型**。

## 11 MVP 范围与验收标准

### 11.1 MVP 定位

> 建设一个支持"公共党建知识库 + 学校/院系个性化知识库"的**独立党建知识问答系统**：能上传和管理权威材料，通过语义检索和重排序生成有依据的回答，展示引用来源，并具备基础权限控制、敏感信息风险提示和后台管理能力。不依赖扣子平台，基于 LangGraph、FastAPI、PostgreSQL、pgvector 和 Vue/React 开发。

### 11.2 MVP 必交付项

1. 公共/学校/院系知识库管理（分级权限）
2. 文件上传与文档解析（PDF/Word/Excel/图片含 OCR）
3. 文本切分与向量化入库（WF-01）
4. 语义检索 + 关键词检索（混合检索）+ 重排序（WF-02）
5. 基于权威材料的问答与**引用来源展示**
6. 过期/冲突/依据不足提示
7. 基础权限控制、敏感信息风险提示
8. 问答记录与操作日志
9. 基础后台管理（知识库维护、用户/权限、日志查看）

### 11.3 MVP 验收标准

| 验收项 | 标准 |
| --- | --- |
| 文档入库 | 上传合法文件后可解析、切分、向量化并入库；非法文件与解析失败有明确错误提示 |
| 知识问答 | 对库内问题给出引用回答；无依据问题拒绝编造；越权文档不被引用 |
| 引用溯源 | 每条引用可定位到文件名称、章节/页码或原文片段 |
| 权限 | 越权访问返回拒绝并可审计 |
| 风险提示 | 命中敏感规则/过期文档时展示风险提示 |
| 工作流 | WF-01 与 WF-02 各自独立运行、可独立测试与审计；单条失败不影响另一条 |
| 交付评审 | 湘潭大学相关教师试用确认知识问答效果、业务流程和数据边界 |

## 12 风险与依赖

| 风险/依赖 | 说明 | 应对 |
