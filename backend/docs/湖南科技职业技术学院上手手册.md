# 党建工作智能体 · 湖南科技职业技术学院使用手册

> 适用对象：本校党委、院系党组织、党支部工作人员，以及全体党员与入党申请人
> 编写日期：2026-10-17（依据当前运行环境与系统实际行为编写）
> 登录地址：http://127.0.0.1:5666 （登录页 `/login`）

---

## 0. 先记住这四句话

1. **AI 只做辅助**：系统负责检索、起草、给建议；**业务结论、阶段认定、归档效力必须由组织人员人工确认**。系统给的任何建议都不构成组织认定。
2. **先建组织、再开账号、再传制度**：三步顺序不能颠倒，否则后面每一步都会卡住。
3. **用哪个学校的账号，就只能看哪个学校的数据**。看不到数据，先检查是不是登录错了账号、或者顶部租户没切对。
4. **所有关键操作都留痕**（审计日志），可追溯、可倒查。

## 1. 三分钟上手

### 1.1 登录

1. 浏览器打开 `http://127.0.0.1:5666`。
2. 输入用户名和密码，登录后默认进入「制度问答」页。
3. 左侧是功能菜单，按角色显示——**你看不到的菜单，说明你的角色没有该权限**，不是系统故障。
4. 退出：右上角退出登录。令牌默认 30 分钟过期，过期后重新登录即可。

### 1.2 界面怎么看

| 区域 | 作用 |
| --- | --- |
| 左侧菜单 | 按「个人 / 问答 / 资料 / 业务 / 系统」分组，只显示你有权访问的页面 |
| 页面顶部 | 当前模块名称与当前组织范围（学校 / 院系 / 支部） |
| 表格行 | 点击任意一行，打开该条记录的详情面板（材料、审核、归档都在详情里操作） |
| 红色报错 | 出现在弹窗顶部，按第 7 节对照表处理 |

### 1.3 关于密码

- 系统**没有自助改密入口**，也不保存明文、不提供找回。
- 忘记密码：找平台管理员停用旧账号、重新开户。
- 开户时设定的密码：**不少于 8 个字符，且不超过 72 个 UTF-8 字节**（中文按 3 字节算）。

## 2. 角色与权限总表

数据范围逐级包含：**本人 < 支部 < 院系 < 学校 < 平台**。

| 角色 | 能看到的菜单 | 数据范围 | 开户时必须绑定的组织类型 |
| --- | --- | --- | --- |
| 平台系统管理员 | 创建账号、系统状态、管理与审核、全部业务页 | 平台（跨校） | 平台（不绑定学校） |
| 学校管理员 | 制度问答、知识库、党员发展、组织生活、中心组学习、年度考核、管理与审核 | 全校（含院系、支部） | **学校** |
| 院系管理员 | 同上 | 本院系（含下属支部） | **院系** |
| 支部书记 | 制度问答、知识库、党员发展、组织生活、年度考核、管理与审核 | 本支部 | **支部** |
| 组织员 | 同上 | 本支部 | **支部** |
| 普通党员 | 制度问答、知识库（只读）、本人档案、个人材料 | 本人 | **支部** |
| 申请人 | 制度问答、知识库（仅公开制度）、本人档案、个人材料 | 本人 | **支部** |

几点必须知道的差别：

- **中心组学习只有学校管理员和院系管理员能用**，支部书记、组织员看不到该菜单。
- **学校管理员独有**：考核指标配置、归档效力确认、学校配置、审计查询、运行日志、渠道自检。
- **支部书记比组织员多一项**：考核归集的人工审核权。
- **制度目录可见范围**：学校管理员＝公开+学校；院系管理员＝公开+学校+院系；支部书记/组织员＝公开+学校+院系+支部；普通党员＝公开+学校；**申请人＝仅公开**。目录显示为空，先看页面空态说明——那是角色范围决定的，不是筛选条件坏了。

> 开户时**角色必须与组织类型严格匹配**：学校管理员挂学校、院系管理员挂院系、其余一律挂支部。挂错会直接报 `422 所选角色与组织类型不匹配`。

## 3. 全员通用：这三个功能人人都会用

### 3.1 制度问答 `/ask`

1. 左侧点「制度问答」。
2. 在输入框输入问题，提交。
3. 系统检索本校知识库后作答，答案下方给出**引用出处**，可点开核对原文。
4. **没有依据时会明确提示"暂无依据"，不会编造**。
5. 「最近提问」按本人账号隔离保存，可逐条删除（只删你的提问记录，不影响制度文件和审计）。

> 回答仅供参考，以组织部门的确认为准。

### 3.2 制度目录 `/knowledge`（只读查看）

1. 点「知识库」，查看授权范围内的制度目录、文件信息与摘要。
2. 点表格任一行打开详情面板，可**下载制度原件**（可指定历史版本）。
3. 上传、废止、移除、改元数据需要院系管理员及以上权限，只读角色看不到这些按钮。

### 3.3 退出与超时

访问令牌 30 分钟、刷新令牌 7 天。超时后重新登录；怀疑账号异常请联系平台管理员吊销令牌。

## 4. 分角色操作步骤

---

### 4.1 平台系统管理员（账号 `admin`）

> 这是**平台侧**账号，负责开户与治理，**看不到任何一所学校的业务数据**。做业务请用学校自己的账号。

#### 步骤 1：登记学校（租户）

1. 进入「管理与审核」→「组织与账号」。
2. 点「登记租户」，填写学校名称与编号，提交。
3. **登记成功后系统不会自动切换过去**——必须在页面顶部「管理租户」下拉里手动选中这所学校，后续操作才落在它身上。

#### 步骤 2：建立组织树（学校 → 院系 → 支部）

1. 确认顶部「管理租户」已切到目标学校。
2. 点「新增组织」，填写：
   - 名称（如"湖南科技职业技术学院党委"）
   - **组织类型：学校**（⚠️ 弹窗默认停在"院系"，必须手动改成"学校"）
   - 上级组织：无上级
3. 提交。表格应立刻出现该行。
4. 再建院系：类型选「院系」，上级选学校党委。
5. 再建支部：类型选「支部」，上级选院系或学校。

层级硬规则：

| 类型 | 上级必须是 | 其他约束 |
| --- | --- | --- |
| 学校 | 无上级 | 同租户只能有一个 |
| 院系 | 学校 | — |
| 支部 | 学校 或 院系 | — |

#### 步骤 3：开账号

1. 进入「创建账号」（或治理页的「新增用户」）。
2. 填写：用户名（**全局唯一**）、姓名、角色、所属组织、密码、确认密码。
3. 提交，提示"账号创建成功"。
4. 把账号密码线下告知本人；**系统不返回密码明文**。

#### 步骤 4：日常治理

| 想做的事 | 操作路径 |
| --- | --- |
| 维护组织 / 停用组织 | 管理与审核 → 组织与账号 → 组织行「维护组织」 |
| 维护账号（改名、换组织、停用） | 组织与账号 → 用户行「维护用户」 |
| 查审计记录 | 管理与审核 → 查询审计记录 |
| 查运行日志 / 问答记录 | 管理与审核 → 查询运行日志 / 查询问答记录 |
| 看系统就绪状态 | 系统状态页（仅平台管理员） |
| 人工审核台账 | 管理与审核 → 人工审核 → 审核材料与结论 → 保存人工结论 |

> 审计日志只记录操作结果与状态码，**不保存报错正文**。用户反馈失败时，请让他把弹窗里的红字原文发给你，再对照第 7 节。

### 4.2 学校管理员（本校账号）

> 数据范围：全校。除业务外，还负责指标配置、归档效力确认、学校配置。

#### A. 知识库（先做，否则问答一律拒答）

1. 点「知识库」→「上传制度文件」→「选择文件」→「上传文件」。支持 PDF / DOCX / TXT / MD。
2. 上传后在列表中点开该文件，右侧「处理与原件」里看处理状态。
3. 状态为「待处理 / 部分可检索」时，点「处理待检索片段」触发向量化；失败可「重试处理」。
4. 处理完成后走复核与审核：
   - 登记复核 → 确认复核（可设复核周期）
   - 登记供给复核确认 → 确认批准 / 确认批准发布，或确认退回修正
   - 最后「确认入库」
5. 制度更新：详情面板「保存元数据」或「保存新版本」。
6. 失效制度：「废止」；彻底删除：「移除」→「确认移除制度文件」。

> 向量化调用云端模型，**会产生云端费用**，请按需上传；只上传经组织部门确认的权威制度。

#### B. 党员发展

1. 点「党员发展」，先选组织（学校/院系/支部），点「查询名册」。
2. 「人工登记培养对象」→ 填写信息 →「保存登记」。
3. 团组织推优：在详情里「登记团组织推优 / 登记推优记录」→「提交审核」→ 审核人「审核选优结论」；有问题「退回登记人修订」。
4. 批次归属：「保存批次归属」；年度批次在流程区「保存年度批次」。
5. 材料：登记待核验材料 → 登记材料人工审核 → 保存培养记录；缺件用「补交材料登记」。
6. 需要参考时可「生成辅助评分」，**只是参考，不构成结论**。
7. 阶段流转：申请人 → 积极分子 → 发展对象 → 预备党员 → 正式党员，用「人工流转 / 登记人工决定」，**必须人工完成**；系统会给出「流转建议」和「待人工确认事项」，提示"暂不建议流转"时不要强行流转。
8. 民主评议/投票：「按年度发起」→「保存草稿」或「保存并送审」→「确认发起」→ 审核人「审核民主评议结果」→「确认审核」。
9. 提醒处理：到期提醒在流程区「登记处理」→「保存处理结果」。
10. 组织关系接转：登记转入 / 登记转出 → 对方「登记接转回执」→ 登记为待接收；错误登记可「确认作废」。
11. 向上级报送：登记报送 → 需要时报材料可「导出台账」。
12. 名册需要纸质留档时点「导出名册」。
13. 党员要用自助功能：在「账号与个人提交」里把党员账号「关联本人档案」。

> 培养期上限：积极分子、预备党员各 365 天（可配置），超期系统提醒。

#### C. 组织生活（三会一课、主题党日）

1. 「登记组织生活计划 / 登记活动计划」，可用「生成议程」或从原文「从原文登记任务」，然后「保存活动计划」。
2. 会后「登记落实 / 登记任务落实结果」→「保存任务记录」；计划取消用「依规取消」并「登记理由」。
3. 纪要：「提交当前纪要审核」→ 审核人「人工审核纪要 / 登记人工纪要审核」，填写「审核意见与依据」→「人工审核通过」。
4. 归档：「归档当前纪要 / 归档已审核纪要」，可查「历史归档」、「导出归档记录」。
5. **电子归档默认关闭**：需由学校先做「电子效力确认版本 / 电子记录效力确认」，登记依据后才具备效力。
6. 修改已归档内容要「保存修改的理由」。

> **登记人与审核人不能是同一个人。**

#### D. 中心组学习

1. 年度计划：「保存年度草案」「保存年度重点」→「提交计划审核」→ 另一位组织人员「通过计划审核」（可填计划审核意见）。
2. 学习活动：「登记学习活动」，可「新增主题 / 新增安排日期 / 新增负责人」，保存新安排；可移除参学登记与摘录。
3. 依据：可「加入年度依据选择」，从知识库选参考制度文件。
4. 纪要：「提交纪要审核」→「通过纪要审核」。
5. 归档：「保存学校归档确认」→「归档已审核记录」；可查「历史归档 / 查看归档详情」、「导出学习材料」。
6. 「修订与审核证据」保留修改痕迹。

#### E. 年度考核

1. **你必须先登记指标**：「新增学校指标 / 新增指标」→「保存指标版本」→ 填写「指标确认依据」。没有指标时系统不会自动导入示例指标。
2. 院系/支部制定任务：新增年度任务 → 关联指标 → 保存任务。
3. 佐证：关联真实佐证 → 选择佐证类别 → 确认佐证版本。
4. 审核：人员阶段登记 → 待人工审核 → 人工审核通过 → 填写归集审核意见 → 确认已核查归集。
5. 提醒：可「扫描提醒」手动触发（系统默认每 300 秒自动扫描一次），到期项「登记处理结果」。
6. 导出：导出材料目录；可查看授权来源详情、历史归集详情。
7. 口径要确认时：「人工确认口径 / 人工确认计划」，保存计划修订版本。

#### F. 治理（本校范围）

| 操作 | 入口 |
| --- | --- |
| 组织维护 | 管理与审核 → 组织与账号 → 维护组织 |
| 既有账号维护 | 管理与审核 → 组织与账号 → 维护用户 |
| 人工审核 | 管理与审核 → 提交人工审核 / 审核材料与结论 → 保存人工结论 |
| 归档效力 | 电子记录效力确认 |
| 学校配置 | 保存学校配置 |
| 提醒扫描 | 党员提醒扫描 / 发展党员提醒扫描 |
| 渠道自检 | 发起渠道自检（默认不投递任何外部消息） |

> 平台系统管理员才能「登记租户」和「新增用户」，学校管理员看不到这两个入口。

### 4.3 院系管理员

数据范围：本院系（含下属支部）。操作与学校管理员基本一致，**差别如下**：

| 事项 | 说明 |
| --- | --- |
| 知识库 | 可上传、复核、审核、废止、移除（具备知识库维护权） |
| 党员发展 | 只能看本院系名册与材料 |
| 组织生活 | 本院系范围，登记与审核须分开 |
| 中心组学习 | 可用，需本院系归属正确 |
| 年度考核 | 可制定任务、关联佐证、导出；**不能登记学校级指标** |
| 治理 | 可维护本院系组织与既有账号；**不能新增用户、不能登记租户** |
| 归档效力确认 | 不具备（学校管理员专属） |

操作步骤：照 4.2 的 A→F 执行，凡涉及"学校级指标""学校归档确认""新增用户""登记租户"的环节跳过。

### 4.4 支部书记

数据范围：本支部。**没有中心组学习菜单**。

1. **党员发展**（日常主战场）：按 4.2-B 的第 1～13 步执行，范围限定本支部。重点：材料登记、人工流转、民主评议发起与审核、组织关系接转。
2. **组织生活**：按 4.2-C 执行。注意登记人与审核人不能同一人。
3. **年度考核**：接收学校下发的指标 →「新增年度任务」→「关联指标」→「保存任务」→「关联真实佐证」→「确认佐证版本」→ 提交后由具备审核权的人「人工审核通过」。**你具备考核归集的人工审核权**。
4. **管理与审核**：可维护本支部组织、维护既有账号、提交人工审核。
5. **制度问答与知识库**：可问答；知识库为只读查阅（无维护按钮）。

---

### 4.5 组织员

与支部书记完全相同，**唯一差别：不具备考核归集的人工审核权**（可以制定任务、关联佐证、导出，但不能点"人工审核通过"）。其余按 4.4 执行。

### 4.6 普通党员

> 前提：必须**先由组织人员在名册中把你的账号明确关联到本人档案**（系统不按姓名自动推断）。未关联时会看到"尚未关联本人档案"，请联系本支部组织人员。

1. **本人档案** `/my-archive`：只读查看本人的基本信息与当前阶段。信息有误请找组织人员修改，本人不能编辑。
2. **个人材料** `/my-materials`：
   - 点「提交材料」，填写标题、类型、说明，上传原件。
   - 支持 PDF / DOCX / TXT / MD / PNG / JPG，默认上限 10MB。
   - 提交有幂等编号，**重复提交不会重复保存**。
   - 可「下载原件」查看自己提交过的材料。
   - 私有原件**不进知识库、不发送给模型**，与制度文件是两套存储。
   - 提交不等于组织核验通过、也不等于阶段变更。
3. **制度问答** `/ask`：同 3.1。
4. **制度目录** `/knowledge`：只读，可下载原件。可见范围为公开 + 学校级。

### 4.7 入党申请人

操作与党员完全相同（本人档案、个人材料、制度问答、只读制度目录）。

**唯一差别**：制度目录**仅公开级**，所以制度目录常常是空的——这是需求规定，不是故障。需要查阅校内制度请向党组织索取。

## 7. 报错对照表

| 报错原文 | 原因 | 怎么处理 |
| --- | --- | --- |
| `422 父组织必须同租户且类型正确` | 组织类型默认停在「院系」却没有上级 | 建学校根组织时手动把类型改为「学校」；建院系/支部时选对上级 |
| `422 同租户只能有一个学校根组织` | 该学校已有学校根组织 | 一所学校只能有一个根组织，其余建为院系/支部 |
| `422 所选角色与组织类型不匹配` | 角色与组织类型不配套 | 学校管理员→学校；院系管理员→院系；其余→支部 |
| `403 请选择当前租户内的有效组织` | 顶部「管理租户」没切到本校 | 先切租户再操作 |
| `404 租户不存在` | 租户编号写错 | 从下拉选择，不要手填 |
| `409 用户名不可用，请更换后重试` | 用户名全局重复 | 换一个用户名 |
| 「培养对象不存在或无权访问」 | 用了平台账号看业务数据 | 业务功能请用本校账号，`admin` 看不到本校名册 |
| 「尚未关联本人档案」 | 组织人员未把账号关联到档案 | 找本支部组织人员在名册里关联 |
| 「模型服务未就绪 / 依赖服务暂不可用」 | 云端模型未配置或不可用 | 联系平台管理员检查模型配置 |
| 制度问答全部拒答 | 知识库为空或未完成向量化 | 先上传制度文件并点「处理待检索片段」 |
| 知识库目录为空 | 角色可见范围决定 | 先看页面空态说明，确认自己角色能看到哪一级 |

## 8. 安全与使用边界

- **出网闸门**：内部数据出网受白名单控制；敏感与涉密内容一律拦截，不因白名单放行。
- **全量审计**：登录、名册读取、材料提交、治理操作均写入审计日志。
- **本人隐私**：党员提交的私有材料不进知识库、不送模型。
- **归档效力**：电子归档默认关闭，需学校确认效力并登记依据后才具备效力。
- **演示数据不是权威依据**：合成名册与演示文档标注"未核验"，正式使用前必须替换为权威资料并人工核对。
- **AI 边界**：系统只做检索、起草与建议，**所有业务结论、阶段认定、归档效力由组织人员人工确认**。
