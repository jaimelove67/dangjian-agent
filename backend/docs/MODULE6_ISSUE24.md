## 剩余任务

- [ ] **M6-01 / P0：形成可交付代码基线。** 将已验证的本地修补及选择性整合整理成可审查提交/PR，包含新增ORM实体、服务、003–005迁移、前端和回归；限定模型资源忽略规则；解决主分支差异，从干净检出验证应用导入、启动、新库升级及旧库升级。提交与发布按仓库流程另行执行。
- [ ] **M6-02 / P0：登记试点租户和组织。** 使用学校认可的真实学校/院系/支部树，为角色绑定正确组织；提供校验过的初始化或管理流程；禁止用合成组织冒充正式数据，无法确认的组织显示待配置。
- [ ] **M6-03 / P1：完成租户、组织及用户管理。** 提供新增/维护/停用、用户角色授权和组织绑定界面及 API；校验父级同租户、组织类型、有效状态与循环关系；权限变更即时生效、敏感操作留痕，公共库管理与校内库写入权限明确。
- [ ] **M6-04 / P0：固化数据分级与模型合规策略。** 记录当前云端聊天/向量/重排方案与原框架本地推理约定的差异及审批边界；配置精确主机白名单、角色可见范围与内容分级；敏感/涉密拦截不可被前端参数或故障降级绕过。敏感业务所需分析仅使用获准校内服务或人工路径。
- [ ] **M6-05 / P1：补齐数据与文件保护。** 提供原文件/归档材料加密存储、授权访问及完整性验证；生产传输使用TLS，数据库/Redis/模型服务限定内网；管理密钥轮换及脱敏日志，保存保留期与软删除/审批物理清理策略。
- [ ] **M6-06 / P1：覆盖完整审计。** 扩展全部模块的读、写、导出、拒绝及失败事件，记录用户、时间、对象、分级、结果、来源及请求编号；业务回滚或未通过鉴权时审计仍有可靠保存路径，摘要不包含人员材料原文、密钥或令牌。

## 验收标准

- 主分支或指定交付分支干净检出可启动及迁移，无缺失源文件；旧数据升级后保持可读，数据库操作有备份与回退证据。
- 同租户跨组织、跨租户、公共/私有库、同租户跨用户会话和新模块接口的权限测试全部通过，无已知高危问题。
- 敏感/涉密内容进入云端调用前被拒绝，故障降级不能外发；合规开关、授权变更和人工审核有持久证据。
- 关键成功、拒绝、失败及导出可审计，日志和公共返回不泄露密钥、令牌或敏感正文；审计数据库账号不能修改/删除既有日志。
- 锁定环境、完整回归、类型检查、覆盖率、实际镜像、负载及备份恢复均有运行版本和结果，未执行项目明确列为未验收。
- 三方审核及组织电子归档确认完成后，方可按批准范围试点；本Issue任务规划不等于上线或部署授权。
