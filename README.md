# 高校智慧党建平台 2.0

高校党建业务管理与智能辅助系统，当前版本 **2.0.0**。React 前端与 FastAPI 后端通过 `/api/v1` 通信，支持按学校、院系、支部和本人范围办理业务。

平台围绕人工登记、独立审核与单独归档组织流程。制度问答提供来源引用，材料提取建议须经用户确认；智能辅助结果不自动形成发展阶段、审核或考核决定。

## 2.0 功能

- **多角色工作台**：平台、学校、院系、支部书记、组织员、党员及申请人分别进入授权工作范围。教师与学生党员共用党员业务角色。
- **组织与党员**：组织名册、本人档案、账号档案关联、发展材料、培养记录、人工阶段流转，以及选优、民主评议、组织关系与上级报送台账。
- **组织生活与校级业务**：会议登记、原件材料、版本核验、提交、独立审核、退回补充、归档与督办。
- **学习教育与考核**：年度学习计划、任务和学习记录，课程、活动报名、视频学习、考试计分、积分，以及年度考核指标、佐证归集、审核与归档。
- **知识与材料**：知识文档版本、原件与引用追溯，个人材料提交及授权接收，DOCX、TXT、MD 和可提取文字的 PDF 填写建议。
- **账号与运维**：租户和账号管理、组织授权、改密申请与一次性批准、会话撤销、安全审计、加密备份及隔离恢复演练。
- **正式系统提示**：页面、弹窗、通知、错误提示及导出使用正式业务用语；功能可用性和操作结果按实际状态显示。

详细变更与验证范围见 [2.0.0 发布说明](docs/releases/2.0.0.md)。


## 开发与运行

需要 Node.js 22+、Python 3.11 或 3.12，以及 PostgreSQL / pgvector 和 Redis。完整配置见 [前后端分离与运行](docs/frontend-backend.md)。

1. 在根目录执行 `npm ci` 安装当前 React 前端依赖。
2. 在 `backend/` 建立虚拟环境，使用 `requirements-dev.lock` 安装开发环境，或使用 `requirements.lock` 安装运行环境；安装时使用 `pip install --require-hashes -r <锁文件>`。
3. 从 `backend/.env.example` 准备 `backend/.env`，配置数据库、Redis、认证及原件加密参数。模型凭据只在服务端配置。
4. 新环境按 [迁移说明](backend/migrations/README.md) 准备数据库；已有数据库升级前先确认目标并完成备份。当前迁移头为 `031_backup_jobs`。
5. 配置完成后，在根目录执行 `npm run dev:all`，统一启动 FastAPI 和 React；前端代理自动指向该次启动的后端。

`npm run dev:frontend` 和 `npm run dev:backend` 可分别启动两端。单独启动前端时，默认使用浏览器工作区数据；连接后端须设置 `VITE_DATA_MODE=live`。后端模式按登录账号校验角色和租户，不回退到浏览器工作区记录。正式账号及初始权限按实际部署流程准备。

| 命令 | 用途 |
| --- | --- |
| `npm run dev:all` | 启动前后端并同步开发代理 |
| `npm run build:frontend` | 独立前端构建至 `frontend/dist/` |
| `npm run build` | 构建根目录 `dist/`，保留 Sites 兼容入口 |
| `npm test` | 当前 React 契约、业务边界和开发入口回归 |
| `npm run test:sites` | 验证 Sites 静态资源及路由兼容 |

## 验证与业务边界

2026-10-24 的功能联调完成了后端 **1,190 项回归**，覆盖率 **85.69%**，以及七角色页面权限、浏览器业务闭环、限定合成模型引用、加密备份和隔离恢复。实际范围与限制见 [前后端联调报告](docs/integration-check-2026-10-24.md)。

随后系统文案更新通过 **89 项前端及开发入口检查**、13 项文档解析检查、4 项构建兼容检查，并核查本地前端八类身份的 86 个可访问页面。该轮检查聚焦文案与缓存兼容，未重新执行后端全业务流程。

这些结果来自隔离合成环境，不代替学校制度确认、真实学校数据验收或生产上线验收。学校模型准入、外部通知、备份服务和隔离恢复目标均须按实际环境配置；恢复演练不自动切换当前业务数据库。
