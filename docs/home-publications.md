# 首页与校内公示

首页按学校管理员、院系/支部管理人员、党员及申请人分别展示，公示公告区共享分类、搜索、详情与附件查阅。平台管理员继续使用独立的运维首页，不提供学校公示查阅和文件发布管理入口。

## 展示与权限

- 公示面向校内登录用户，按租户与组织树确定接收范围；上级组织发布的信息可供接收范围内的下属组织人员查阅。
- 首页仅展示已发布、处于展示期限内的信息。公示的开始日和截止日当天均包含在内，前后端统一按北京时间判断。
- 个人材料与公示文件分别存储和展示。个人提交记录不作为发展材料核验或组织认定的依据。
- 学校管理员可通过首页“发布管理”编制公示或通知。院系、支部与个人角色只有查阅入口，本次未扩大通知发布权限。
- 接口失败时展示对应来源的错误和重试入口；成功取得的其他来源保留。真实模式不回退本地记录，不能取得的统计不显示为零。

## 编制和发布

沿用 `POST /api/v1/school/business/notices`，兼容原有通知参数，增加：

| 字段 | 含义 |
| --- | --- |
| `category` | `notice`（默认）或 `publicity` |
| `starts_on` | 开始展示日期 |
| `expires_on` | 截止展示日期 |
| `doc_ids` | 最多30份已发布、授权原件的文件编号 |

公示事项必须填写开始和截止日期，开始日期不得晚于截止日期。保存草稿与确认发布分别办理、分别留痕，草稿不进入首页。当前流程为学校管理员保存草稿后单独确认发布，未新增他人独立审核、更正或撤回流程。

真实模式附件先由党建工作库上传、核对并发布，再在公示草稿中选择。服务端检查密级、组织范围、原件及版本，禁止将范围较窄或敏感的文件挂到更大范围的通知上。正式发布前再次核对附件状态与版本。详情下载仍经过知识文件授权接口，并指定公示关联的原件版本。

本地模式可随草稿上传一份10MB以内的 PDF、DOCX 或 TXT 原件，独立保存在 IndexedDB 的公示命名空间中。下载校验租户、组织、发布状态、期限及附件所属记录；不会读取本人材料命名空间。原件未上传的历史登记如实提示，不能生成虚构下载结果。

## 首页办理入口

学校管理员首页合并展示会议和校级业务任务。计数及进度明细先打开当前范围的事项列表，再按来源进入对应办理页面，避免统计包含的记录在目标页丢失。党员首页只列本人任务、个人提交记录与所属组织活动提示；个人任务支持直达具体业务记录。

## 验证边界

本轮完成前端回归、构建及 Sites 兼容检查、后端隔离数据库的公示工作流测试，并使用隔离浏览器检查桌面和窄屏页面。本地流程覆盖草稿、确认发布、授权党员查阅和原件读取；真实模式浏览器检查使用拦截接口，未连接真实业务数据库或执行部署。
