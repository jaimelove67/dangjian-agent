# 本地预览登录故障修复

核对时间：2026-10-24。

本次故障已由实际请求复现：`127.0.0.1:18001` 无法连接，而 `4177` 的 Vite 仍在运行。Vite 默认将连接上游失败转换为空正文的 HTTP 500，前端只能显示“请求失败（HTTP 500）”。请求当时没有到达认证接口，因此不是密码校验失败。

已恢复原隔离数据库、Redis 和材料目录，并改为工具托管的前台后端会话。新增 `backend/scripts/start_local_preview.py` 使用 Git 忽略的 `backend/.env.local-preview.json` 保存本地配置，重启不再依赖已退出进程的 PID 或内存环境。脚本只接受 testing 环境及指定的本机数据库 / Redis，关闭后台任务和模型调用，不开户、不重置密码。

用户同时在另一聊天移动前端目录；旧预览因仍指向原目录曾返回 404。已将同一 `4177` 预览进程切到现有 `frontend/`，没有撤回该目录调整。

`frontend/vite.config.mjs` 现在仅对代理连接失败返回带明确说明的 JSON 503。真实后端的 500 响应、正文和请求 ID 保持原样。`frontend/tests/dev-proxy.test.mjs` 已用真实临时 Vite 先复现失败，再验证两项修复检查；当时完整前端测试 69 项、构建及 4 项 Sites 检查通过。之后的目录整理由另一聊天继续维护。

当前登录已验证：

- 相同的登录复现脚本从 HTTP 500 变为 HTTP 200，并取得真实会话；脚本不输出令牌或密码。
- 平台管理员、学校管理员、普通党员均通过真实浏览器表单登录并进入各自工作台。
- 普通党员可下载故障恢复前上传的合成加密材料，内容校验通过。

证据位于 `tmp/qa/login-repair.json` 和 `tmp/qa/login-repair-school-dashboard.png`。预览仍为 `http://127.0.0.1:4177/`；关闭本地运行会话或 Docker 后需要重新启动对应服务，这不是线上部署。
