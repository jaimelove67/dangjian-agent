## 设计依据

使用项目原有 `.workbuddy/skills/design-taste-frontend/SKILL.md`，即 taste-skill。
该技能 Section 13 明确不覆盖管理面板、数据表和复杂业务表单。本次结合业务场景复用其
字体、颜色、信息层级、克制动效与响应式原则，沿用 Vue 3 和现有原生 CSS 设计系统。

设计定位：面向党务工作人员的正式业务工作区，强调材料来源、操作步骤、权限和人工确认。
参数：`DESIGN_VARIANCE=3`、`MOTION_INTENSITY=2`、`VISUAL_DENSITY=5`。

- 暖白底色与砖红强调色 `#a03230`；状态颜色仅表达业务语义。
- 延用正文系统字体、文件式标题及四档圆角，不新增运行时依赖。
- 主操作、材料依据、办理记录分层呈现；次要维护操作按需展开。
- 表格在容器内滚动；表单在手机上改为单列。
- 页签支持方向键、Home、End；原生弹窗支持焦点限制、Escape 和关闭后的焦点返回。
- 复用现有焦点样式、减少动效偏好及可排障的错误组件。

原始界面在提交 `8d2eb1f22784bb0a9fd3a4d3074c91d51b06a053` 的隔离工作区截图。
两版截图均来自浏览器内接口样例；其内容不构成业务材料或组织结论。

## 实现范围

| 模块 | 新增正式入口 | 关键业务约束 |
| --- | --- | --- |
| 知识库 | 正文处理状态、处理或重试、分版本原件下载、元数据修正 | 下载携带授权头，令牌不放入 URL；来源、时效、可见范围和密级由后端再校验；修正必须提供理由 |
| 党员发展 | 人员办理档案、年度批次、材料审核与历史、培养证据、年度评分、人工流转、提醒处理、多轮投票、档案检查 | 规则分析和评分不自动流转；人工决定记录日期、依据和意见；材料名称登记不等于原件已核验；投票提交前逐项确认 |
| 组织生活 | 活动计划与资料编辑、参会及出勤、参考资料选择、议程与纪要（按活动类型切换栏目）、任务办理、版本与归档、年度统计、组织生活频次合规、民主评议党员（按年度发起、程序与等次录入、送审与审核、低等次提示） | 先保存资料再处理当前版本；原文变化后重新提取纪要；禁止自审；组织生活会用「查摆问题 / 批评意见 / 整改方向」栏目；民主测评只存汇总票数、等次与处置由人工形成；归档条件由服务端决定；权限变更后隐藏受限正文与任务 |

新增共用组件：`WorkspaceTabs`、`ActionDialog`、业务表单与表格样式。
组织生活页面拆为独立工作区、参会编辑器和参考资料选择器。
知识库详情优先显示处理状态与原件操作，文件来源及正文更新使用展开区。
党员发展的规则辅助核对入口保留在办理档案下方，人工登记与辅助建议分别呈现。

## 最小后端补充

原名册接口只有分页，无法为年度批次和选优页面提供完整筛选。
`GET /member/roster` 新增可选 `year`、`batch_no`，在计数和分页前执行过滤。
响应增加已有字段的年度和批次；继续使用原租户、组织和有效人员过滤条件，无数据库迁移。

## 验证限制和现有业务边界

- 当前 PostgreSQL 测试端口不可用；未完成真实 PostgreSQL、Redis、模型及多人同时办理的联调。
  浏览器样例验证和输入模型校验不代表真实服务联调已通过。
- 当前投票后端按批次号和轮次归集，不包含年度字段。界面明确提示跨年度使用不同批次号。
  本次没有扩展投票存储模型或声称已具备固定年度候选名单快照。
- 材料页面登记名称、版本和人工核验结果；原件仍按学校档案流程留存。
- 来源权限、电子档案效力和规则适用范围依赖后端及学校配置；界面不生成默认组织结论。
- 本轮是界面实现与相关查询补充。问答评测样本集、真实通知发送和语音能力等未纳入本次验收。
