## 1. 系统能做什么

基于 LangChain / LangGraph / FastAPI 的高校党建工作辅助系统，主要能力：

| 能力 | 模块 | 入口 |
| --- | --- | --- |
| 制度问答（RAG，带引用） | 知识问答 | `/ask` |
| 知识库管理（上传/检索/向量化）；基层角色只读制度目录 | 知识库 | `/knowledge` |
| 党员发展全流程（名册/材料/批次/阶段/投票） | 党员发展 | `/members` |
| 党员与申请人本人档案查询、私有材料提交 | 党员自助 | `/my-archive`、`/my-materials` |
| 中心组年度学习与纪要审核归档 | 中心组学习 | `/study` |
| 年度考核（指标/任务/佐证/提醒/导出） | 年度考核 | `/assessment` |
| 组织生活任务台账 | 组织生活 | `/meeting` |
| 账号开户、治理、系统状态 | 系统管理 | `/accounts`、`/governance`、`/system` |

所有 AI 结论都需要人工审核；发展党员等关键操作必须由组织人员人工完成阶段流转。

## 2. 登录与角色

### 2.1 登录

浏览器打开 `http://127.0.0.1:5666`，在 `/login` 输入用户名和密码。

### 2.2 角色权限一览

| 角色 | 说明 | 主要入口 |
| --- | --- | --- |
| `system_admin` 系统管理员 | 平台级；开户、治理、系统详情 | `/accounts` `/governance` `/system` |
| `school_admin` 学校管理员 | 全校业务管理 | `/members` `/study` `/assessment` `/meeting` `/knowledge` |
| `department_admin` 院系管理员 | 本院系业务管理 | 同上（范围限定本院系） |
| `branch_secretary` 支部书记 | 本支部业务管理 | 同上（范围限定本支部，无中心组学习） |
| `organizer` 组织员 | 组织业务协助 | 同支部书记（范围限定本支部） |
| `member` 普通党员 | 本人档案、材料、问答、制度目录 | `/my-archive` `/my-materials` `/ask` `/knowledge` |
| `applicant` 申请人 | 与普通党员相同 | 同上 |

> 权限边界由「角色 × 所属组织」共同决定；敏感和涉密内容禁止发送云端处理。
> 申请人权限是党员权限的子集（当前两者相同），不存在"低角色可见、高角色被隐藏"的入口。
> 知识库对基层角色是**只读制度目录**，维护操作需 `knowledge.manage`（院系管理员及以上）。

### 2.3 本地测试账号

测试账号由初始化脚本和「创建账号」页面共同产生，**请以脚本实际输出为准**；
密码在创建时由你指定，系统不提供任何默认密码。

| 账号 | 角色 | 归属 | 来源 |
| --- | --- | --- | --- |
| admin | system_admin | PLATFORM_TENANT（平台） | `scripts/dev_bootstrap.py` |
| test-reviewer | school_admin | TEST_TENANT / TEST_ORG | `scripts/dev_bootstrap.py` |
| branch-secretary | branch_secretary | TEST_TENANT / TEST_BRANCH | `scripts/dev_bootstrap.py` |
| test-dept / test-organizer / test-member / test-applicant | department_admin / organizer / member / applicant | TEST_TENANT 下对应组织 | 用 admin 登录 `/accounts` 创建，或用 `dev_bootstrap.py --with-sample-roles` |

初始化命令（幂等，重复执行会跳过已存在的数据）：

```powershell
.\.venv\Scripts\python.exe scripts\dev_bootstrap.py --password Test123456 --with-sample-roles
```

`--with-sample-roles` 会额外创建院系管理员、组织员、党员、申请人四个账号，密码与
`--password` 相同。普通党员与申请人还需要在 `/members` 中由组织人员**明确关联本人档案**，
才能看到本人档案与提交材料。

## 3. 平台管理员操作

### 3.1 创建账号（/accounts）

1. 用系统管理员登录，进入「系统 → 创建账号」。
2. 填写：用户名（全局唯一）、姓名、角色、所属组织、密码（≥8 字符且 ≤72 个 UTF-8 字节）。
3. 角色与组织绑定规则：
   - 学校/院系管理员 → 绑定学校/院系
   - 支部书记、组织员、党员、申请人 → 绑定支部
4. 创建成功即可登录；**不返回密码明文**，请告知用户自行保管。

### 3.2 系统状态（/system）

- 查看运行状态、依赖（数据库/Redis/模型）就绪详情。
- `/api/v1/admin/health` 与 `/api/v1/admin/health/ready` 仅平台管理员可访问。

### 3.3 治理（/governance）

- 租户、组织、账号、业务配置、人工审核与运维治理。
- 组织类型约束：学校根组织无父级；院系父级为学校；支部父级为学校或院系。

## 4. 学校/支部管理员操作

### 4.1 党员发展（/members)

- **名册**：本权限范围内的培养对象名单，按支部查看。
- **批次**：按年度/批次管理发展计划。
- **材料与阶段流转**：登记组织材料，人工完成 申请人→积极分子→发展对象→预备党员→正式党员 的阶段流转；辅助结果不构成组织认定。
- **投票**：支部会议投票。
- 培养期上限：积极分子/预备党员各 365 天（可配置），超期会有提醒。

### 4.2 中心组学习（/study）

- 年度学习计划、条目、共用活动。
- 会议纪要上传与修订，**由另一位组织人员审核**后归档；电子归档默认关闭，需学校确认效力后登记依据。

### 4.3 年度考核（/assessment）

- 流程：学校管理员登记年度指标 → 院系/支部制定任务 → 绑定佐证与归集。
- 站内提醒随后端启动自动扫描（默认 300 秒），也可在工作台手动扫描。
- 没有指标时不会自动导入示例指标。

### 4.4 组织生活（/meeting）

- 组织生活任务台账，登记与跟踪三会一课、主题党日等。

### 4.5 知识库（/knowledge）

- 上传制度文件（PDF/DOCX/TXT/MD 等），自动切分。
- 向量化通过云端 Embedding 模型（`qwen3.7-text-embedding-flash`，1024 维），**会产生云端费用**。
- 检索策略：混合检索 + 重排（`qwen3.7-text-rerank`），支持按可见范围（公开/学校/院系/支部）。
- 点击表格任意一行打开详情面板，可**下载原件**（可指定历史版本）、查看向量化处理状态、修正文档元数据。
- 处理状态为"待处理/部分可检索"时，在详情面板点"处理待检索片段"触发向量化；失败原因会直接显示。

## 5. 普通党员自助

### 5.1 前提

普通党员账号需由组织人员在名册中**明确关联**到本人档案后，才能使用本人档案功能（系统不按姓名自动推断）。

### 5.2 本人档案（/my-archive）

- 只读查看本人档案，包含组织登记的基本信息与阶段。

### 5.3 私有材料（/my-materials）

- 填写标题、类型、说明并上传原件；支持 PDF、DOCX、TXT、MD、PNG、JPG/JPEG，默认上限 10MB。
- 提交有稳定重试编号，重复提交不会重复保存；可下载本人提交的原件。
- 私有原件**不进入知识库、不发送模型**。

### 5.4 制度问答（/ask）

- 输入问题，系统基于知识库检索并引用来源作答。
- 无依据时系统会明确提示，不强行编造；所有回答仅供参考，以组织部门确认为准。
- "最近提问"按本人账号隔离保存，可逐条删除；删除只影响该条记录，制度文件与审计记录保留。

### 5.5 制度目录（/knowledge）

- 基层角色（党员、申请人）可只读查阅授权范围内的制度目录、文件信息与摘要。
- 可见范围按角色区分：普通党员为公开 + 学校级；申请人按需求规定**仅公开**。若目录为空，先看空态说明——它来自角色范围而不是筛选条件。
- 打开详情面板可**下载制度文件原件**（与"私有材料"不同，制度原件来自组织上传的知识库文件）。
- 上传、废止与移除需要 `knowledge.manage`，仅院系管理员及以上具备；只读角色看不到元数据修正表单。

## 6. 常见问题

| 现象 | 原因与解决 |
| --- | --- |
| 「培养对象不存在或无权访问」 | 账号范围不对：平台账号没有组织数据，业务功能请用学校/支部账号 |
| 「模型服务未就绪 / 依赖服务暂不可用」 | 检查 `.env` 的 `DASHSCOPE_API_KEY` 与 `CHAT_MODEL`（本项目验证可用 `qwen3.8-flash`；`deepseek-v3` 在该账号不存在） |
| `/api/v1/health/ready` 返回 503 | 必需依赖（数据库/Redis/业务结构/模型配置）缺失；详情见“系统状态”页或 `/api/v1/admin/health/ready` |
| 系统状态页显示“模型连通性：未验证” | `model_warm` 是观察项，15 分钟内没有成功模型调用时如此，不影响就绪；做一次正常问答即可转为已验证 |
| 登录不了 | 确认账号已开户且在同一租户/组织有效；无默认密码 |
| 前端提问超时 | 首次模型调用可能较慢；可在后端日志查看模型返回 |
| 端口冲突 | 本机 8000 已被占用时，按 `.env` 的 `APP_PORT` 启动后端，并用 `VITE_API_TARGET` 指向前端代理 |

## 7. 安全与使用边界

- **数据闸门**：内部数据出网受白名单限制（`ALLOWED_EXTERNAL_MODELS`）；敏感与涉密内容不因白名单放行。
- **审计**：登录、名册读取、材料提交、治理操作均写入审计日志。
- **会话**：访问令牌默认 30 分钟、刷新令牌 7 天；支持吊销。
- **演示数据**：合成名册与演示知识文档标注「未核验演示」，正式使用请替换为权威资料并人工核对。
- **生产环境**：`ENV=production` 强制 PostgreSQL TLS、Redis TLS、强密钥、文件加密密钥环与明确访问来源；不建议直接改 `.env` 上生产。
