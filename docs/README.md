## 文档维护

- 同一主题更新现有指南；阶段性检查只在有必要保留独立证据时归档。
- 功能变化更新 `STATUS.md`，启动变化更新 `RUNNING.md`，测试变化更新 `TESTING.md`。
- 测试记录注明日期、被测版本或工作区、执行命令、环境、失败与跳过数，以及未验证范围。
- 生成的日志、覆盖率与评测结果写入 `tmp/test-results/`；不在 `docs/` 累积自动生成报告。
- 归档中的“完成”“100%”等结论仅代表当时记录；当前验收边界见项目状态和测试指南。

原始需求 `require.txt` 保留需求基线；按日期命名的报告保留当时结果，不刷新成当前验收结论。框架中的规划能力与已实现能力须分别阅读，当前功能以 `STATUS.md` 和实际代码为准。
