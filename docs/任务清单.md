> 编制日期：2026-10-13。最近校准：2026-10-15（逐条对着工作区的路由、服务、迁移复核状态，见文末「校准记录」）。基线：`docs/STATUS.md`、`docs/PROJECT_OVERVIEW.md`、`docs/TESTING.md`、`migrations/README.md`。

## 0 使用说明

### 0.1 字段含义

每条任务采用统一字段：

```
- [ ] T-<模块>-<序号> | 任务名 | <优先级> | <实现状态>
      来源：FR/SEC/NFR/WF 编号
      依赖：任务 ID
      验收：可验证的完成标准
```

### 0.2 任务 ID 规则

`T-<模块码>-<两位序号>`，模块码与原需求模块对齐：

| 模块码 | 含义 | 对应需求 |
| --- | --- | --- |
| INFRA | 基础设施与环境 | 2.1 |

| WF01 / WF02 | 工作流 | 6.1 / 6.2 |

### 0.3 优先级

- **P0**：第一阶段 MVP（需求文档 §10）
- **P1**：第二阶段业务智能体
- **P2**：第三阶段产品化

### 0.4 状态标记（与实现状态统一口径）

> 勾选框是 0.5「实现状态」的视觉速记，二者必须一致，不得各写一套。
> **勾选 ≠ 已通过业务验收**：验收结论以 §11.3 验收表、§1.10 必交付项对照和附录 C 里程碑为准。

| 标记 | 对应实现状态 | 含义 |
| --- | --- | --- |
| `[x]` | ✅ 已实现 | 当前工作区已有对应代码，任务转为**验收 / 加固** |
| `[~]` | ⚠️ 部分实现 | 部分完成或有明确边界未闭环 |
| `[ ]` | ❌ 未实现 / 🔒 前置闸门 | 需开发，或依赖外部确认未闭环 |

### 0.5 实现状态（校准列）

| 标记 | 含义 |
| --- | --- |
| ✅ 已实现 | 当前工作区已有对应代码，任务转为**验收 / 加固** |
| ⚠️ 部分实现 | 部分完成或有明确边界未闭环 |
| ❌ 未实现 | 尚无实现，需开发 |
| 🔒 前置闸门 | 依赖外部确认，未闭环不得进入业务验收 |

> 实现状态依据 `docs/STATUS.md`（2026-10-11）。历史分支证据不代表当前工作区已验收。

### 0.6 责任分工（RACI）

> 任务能否闭环不只看代码，还取决于责任人是否到岗。以下角色必须**实名指定**，不能只作为"系统功能"存在。

| 角色 | 职责 | 关联任务 | 建议人选 |
| --- | --- | --- | --- |
| 党务业务负责人 | 业务流程确认、内容供给、审核规则制定 | T-KB-12、T-KB-13、T-MILE-01 | 学校组织部门 / 学院党委指定 |
| 知识库内容审核人 | 权威来源审定、版本与效力状态维护 | T-KB-12、T-KB-13 | 学校组织部门 / 宣传部 |
| 人工终审责任人 | 评分 / 选优 / 结论类输出终审，**不得由原提交人兼任** | T-SEC-13、T-MEM-10、T-MEM-13 | 支部上级党组织 / 院系管理员 |
| 电子效力确认人 | 归档留痕合规性与效力确认 | T-GATE-01、T-ORG-08 | 学校组织部门 |
| 合规审核组 | 出网、涉密、合规联合审核 | T-GATE-02、T-SEC-12 | 组织 / 信息化 / 保密部门 |
| 质量评测复核人 | 评测样本与专家答案复核 | T-QA-EV-01~03 | 党建业务专家 + 项目组 |
| 技术负责人 | 开发、加固、部署与运维 | 全部 T-INFRA / T-WF / T-SYS / T-NFR | 项目组 |
