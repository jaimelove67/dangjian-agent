**两条总原则**（写在使用之前）：

1. **系统只做辅助，不做认定。** 阶段流转、纪要归档、考核结论、选优名单，一律由具备权限的组织人员人工登记；界面上的"资格校验""流转建议""评分"都只是核对参考。
2. **权限 = 角色 × 所属组织。** 角色决定你能看到哪些菜单，所属组织决定你能看到哪些数据。两者缺一都打不开功能。

## 1. 系统总览

### 1.1 系统定位

面向高校党建工作的智能辅助系统（LangChain / LangGraph + FastAPI + Vue3），做四件事：

- **答得准**：基于本单位的党内法规与校内制度作答，逐条标注出处，可溯源、可核对。
- **管得住**：党员发展、组织生活、中心组学习、年度考核四条业务线全流程留痕。
- **审得过**：关键动作必须人工审核，且**提交人不能自审**。
- **出得去**：考核材料、学习材料、发展台账均可导出归档。

### 1.2 模块地图

| # | 模块 | 路径 | 主要使用角色 | 一句话 |
| --- | --- | --- | --- | --- |
| 1 | 制度问答 | `/ask` | 全体 | 带引用的制度问答，依据不足会明确提示 |
| 2 | 知识库 | `/knowledge` | 院系管理员及以上可维护；基层只读 | 制度文件入库、向量化、分级授权 |
| 3 | 党员发展 | `/members` | 支部/院系/学校 + 平台 | 名册、材料、批次、阶段流转、投票、上报、接转 |
| 4 | 组织生活 | `/meeting` | 支部/院系/学校 | 三会一课、主题党日、任务台账、民主评议 |
| 5 | 中心组学习 | `/study` | 学校/院系管理员 | 年度计划、每期学习、纪要审核与归档 |
| 6 | 年度考核 | `/assessment` | 学校/院系/支部 | 指标、任务、佐证、归集、计划草案、导出 |
| 7 | 本人档案 | `/my-archive` | 党员、申请人 | 只读查看本人档案 |
| 8 | 个人材料 | `/my-materials` | 党员、申请人 | 提交私有材料原件 |
| 9 | 创建账号 | `/accounts` | 平台管理员 | 为本单位人员开户 |
| 10 | 治理 | `/governance` | 平台/学校/院系 | 租户组织账号、人工审核、学校配置、任务、审计 |
| 11 | 系统状态 | `/system` | 平台管理员 | 连通性、就绪、模型走向、接口诊断 |

### 1.3 访问方式与部署形态

| 环境 | 地址 | 说明 |
| --- | --- | --- |
| 线上（当前） | `http://129.204.32.148` | 单机四容器：Nginx 前端 + FastAPI + PostgreSQL(pgvector) + Redis |
| 本地开发 | 前端 `http://127.0.0.1:5666`，后端 `http://127.0.0.1:18000` | 见 `docs/RUNNING.md` |

浏览器打开首页自动跳 `/login`，登录后默认落在 `/ask`。支持 Chrome / Edge 最新版。

### 1.4 数据是怎么流转的

```
制度文件 ──上传──> 知识库 ──切分·向量化──> 检索库 ──> 制度问答（带引用作答）
                                                        ↓
业务台账（发展/生活/学习/考核）──登记·审核──> 归集统计 ──> 考核材料导出
                                                        ↓
                                                  审计日志（全量留痕）
```

所有读、写、导出都写入审计日志，可按人、按动作、按时间查询与导出。

## 2. 角色与权限

### 2.1 七类角色

| 角色 | 权限码特征 | 数据范围 | 典型岗位 |
| --- | --- | --- | --- |
| 系统管理员 `system_admin` | 全部治理权限 | 平台 + 全部租户 | 平台运维 |
| 学校管理员 `school_admin` | 管理权限全集 + 考核配置、归档确认 | 全校 | 学校组织部 |
| 院系管理员 `department_admin` | 管理权限全集 | 本院系 | 院系党务 |
| 支部书记 `branch_secretary` | 支部管理 + `assessment.review` | 本支部 | 支部书记 |
| 组织员 `organizer` | 支部管理（**无** `assessment.review`） | 本支部 | 组织员 |
| 党员 `member` | 问答 + 只读知识库（公开+学校）+ 本人自助 | 本人 | 党员 |
| 申请人 `applicant` | 同上，知识范围**仅公开** | 本人 | 入党申请人 |

> 支部书记与组织员的唯一差别：支部书记有考核"人工审核"权（`assessment.review`），组织员没有。
> 中心组学习 `/study` 只有学校/院系管理员能看到（需 `study.query`）。
> 平台管理员与学校管理员**没有** `member.self_query`，因此看不到"本人档案/个人材料"菜单。

### 2.2 关键权限码对照

| 权限码 | 作用 | 谁有 |
| --- | --- | --- |
| `knowledge.manage` | 上传、废止、元数据修正、触发向量化 | 院系管理员及以上 |
| `knowledge.review` | 批准/退回知识文档 | 院系管理员及以上 |
| `member.stage_transition` | 登记培养对象、导入名册、人工流转 | 支部及以上管理角色 |
| `study.query` / `study.manage` | 中心组学习查看 / 维护 | 学校、院系管理员 |
| `assessment.configure` | 登记与修订考核指标 | 学校管理员 |
| `assessment.review` | 考核人工审核 | 学校、院系、支部书记 |
| `assessment.export` | 导出考核材料目录 | 学校、院系 |
| `admin.identity` | 治理页"组织与账号" | 平台、学校、院系 |
| `admin.config` | 治理页"学校配置"、渠道自检 | 平台、学校 |
| `admin.ops` | 治理页"运行审计" | 平台 |
| `admin.audit` | 治理页"问答记录" | 平台、学校 |

> 权限码可在 `/system` 页面"当前账号"卡片里直接看到自己的全部权限码。菜单按权限码显隐——缺哪一项，对应入口不会出现。

### 2.3 组织树硬规则

学校根组织 → 院系 → 支部，三级：

- 同一租户**只能有一个** school 根组织，school 不能有父级；
- department 的父级必须是 school；
- branch 的父级是 school 或 department。

违反规则提交会返回 422，页面给出提示。

## 3. 通用操作

### 3.1 登录与退出

浏览器打开站点 → `/login` → 输入用户名与密码。登录成功后默认进入 `/ask`。访问令牌 30 分钟、刷新令牌 7 天，超时回到登录页。

### 3.2 界面布局

左侧为功能菜单（按权限码显隐），顶部为模块页签，主体为工作区。多数业务模块采用"左列表 + 右详情"或"页签 + 卡片"布局。

### 3.3 报错时先做一件事：记下请求标识

任何错误页都会显示 **请求标识（trace_id）**，并提示"（反馈问题时请提供此标识）"。常见错误页：

| 错误页标题 | 含义 |
| --- | --- |
| 权限不足（40301） | 角色没有该操作的权限码 |
| 数据范围校验未通过 | 当前账号所属组织无权访问该数据 |
| 登录状态已失效 | 令牌过期，重新登录 |
| 请求过于频繁 | 触发限流，稍后重试 |
| 依赖服务暂不可用 | 后端依赖（数据库/Redis/模型）异常 |
| 无法连接到服务 | 后端未启动或网络不通 |

无权限访问某页面时会落到"无法访问该页面"，提示联系平台系统管理员核对**角色与所属组织**。

### 3.4 通用填写规范

- 带 `*` 为必填；有未保存改动时，多数"生成/送审/审核/归档"按钮会被禁用，提示"当前修改尚未保存，请保存后再…"。
- 关键动作均需填写 **操作理由/审核意见**（必填）并勾选确认，例如"我已核对材料、时限及组织决定，确认登记这次人工流转。"
- 二次确认弹窗标题形如 `确认{动作名}`，勾选后才可提交。

## 4. 分模块操作手册

### 4.1 制度问答 /ask

**用途**：以党内法规与校内制度为依据作答，并逐条标注出处。全体角色可用。

**界面**：左侧会话栏（`新对话` + `最近提问`）→ 中间对话流 → 底部吸附输入框。顶栏有 `会话列表`、`清空`。

**提问操作**：

1. 输入框输入问题，**最多 500 字**（实时显示剩余字数，少于 40 字变警示色）；占位提示为"用一句话描述你要确认的制度问题，例如：发展对象的政治审查需要哪些材料"。
2. `Ctrl/Cmd + Enter` 或点 `提问`；检索期间按钮显示"检索中"。
3. 检索参数固定（`data_level=internal`、`top_k=10`、开启重排序），界面无开关。

**看答案时要注意的三件事**：

1. **引用角标**：答案中的 `[n]` 是可点击的小徽标，点击后滚动定位到对应来源卡并高亮。
2. **溯源卡**字段：文档编号、文件名、生效日期、发文机关、文号、条款、原文片段、检索相关度（高度匹配 / 较相关 / 相关度偏低）。系统会注明"相关度为机器检索排序依据，不作为结论强度"。
3. **顶部结论条**——先看这个，再看正文：

   | 结论条 | 原文提示 |
   | --- | --- |
   | 依据不充分 | 「检索到的片段不足以支撑确定回答。请补充提问条件，或向上一级党组织确认。」 |
   | 未引用依据 | 「回答未标注具体来源，请谨慎采信。」 |
   | 依据充分 | 「本次回答引用了 N 条来源。请逐条核对后再采用。」 |

另有"引用核验提示"（需复核 / 时效两档）与"检索明细"（命中片段、实际引用、依据充分、重排序）。

**最近提问**：每页 8 条，可翻页；点条目回看历史回答（提示"当前展示历史回答，引用的文件可能已经更新或失效。再次提问会重新检索。"）；右侧 × 删除，弹窗标题"删除这条提问记录"，说明"仅从『最近提问』中删除，不影响制度库文件与审计记录。删除后无法恢复。"。空态："尚无问答记录，提问后会保存在这里。"

### 4.2 知识库 /knowledge

**用途**：查阅授权范围内的制度目录；有 `knowledge.manage` 时可维护用于检索的制度文件。

**界面**：页签「全部 / 有效 / 已失效 / 已废止」（带计数）→ 筛选条（搜索 + 层级 + 审核状态 + 复核状态）→ 文档表格 → 底部「文件详情」抽屉。顶部有 `紧凑/舒适`、`上传文件`。

#### A. 查阅（全体角色）

- 表格列：标题（含文档编号）、发文机关、层级、可见范围、权威来源、生效、失效、状态（+ 即将到期 / 待复核徽标）、操作。
- 点击任意一行打开底部详情抽屉，可下载原件。
- 权限不足时："授权范围内暂无可读文件"；申请人专用提示："按权限设定，申请人只能查阅公开制度……"

#### B. 上传（需 `knowledge.manage`）

1. 点 `上传文件` 展开面板，选择文件。
2. **格式与大小**：支持 `.pdf .docx .doc .wps .txt .md .png .jpg .jpeg .webp .tif .tiff .xls .xlsx`，单个文件 **不超过 10 MB**；超限报"文件超过 10 MB，后端会拒绝接收"。
3. 填写元数据：

   | 字段 | 说明 |
   | --- | --- |
   | 文档编号 | **必填，入库后不可修改**（系统自动生成 `DOC-` 前缀） |
   | 标题、发文机关、文号 | 文号选填 |
   | 效力层级 | 中央 / 省级 / 校级 / 院系 |
   | **可见范围** | 公开 / 校内 / 院系内 / 支部内 |
   | 数据分级 | 公开 / 内部 / 敏感 / 涉密 |
   | 权威来源 | 按层级自动推定 / 党章 / 党内法规 / 上级文件 / 学校制度 / 参考资料 |
   | 效力状态、生效日期、失效日期 | — |
   | 标签、摘要 | 便于检索与展示 |

4. 扫描件警告：系统会提示"扫描件（图片型 PDF）与照片没有文字层，系统读不出正文"——这类文件无法向量化。

#### C. 处理与原件（详情抽屉下半部）

- `刷新状态`：查看状态徽标——待处理 / 部分可检索 / 可检索 / 处理失败 / 没有可处理的正文；并显示正文片段、已处理、待处理三项计数与正文版本号。
- **`处理待检索片段`**（失败时文案变为「重试处理」）：触发云端向量化，**会产生云端费用**。条件：有 `knowledge.manage` 且存在待处理片段；**数据分级为"涉密"时禁用**，提示"涉密资料不提供在线向量处理"。成功后提示"本次处理 N 个片段，检索状态已刷新。"
- `下载原件`：可选择原件版本号（1 ~ content_revision）。"历史原件按当前权限检查；早期未留存的版本会提示无法下载。"
- `修正文档元数据`（折叠，仅 `knowledge.manage`）：可改标题、发文机关、文号、制度层级、可见范围、数据分级、权威来源、效力状态、生效/失效日期、标签、摘要；**修正理由必填**，否则保存按钮禁用。保存后提示"元数据已保存，变更理由已留存。"

#### D. 维护动作

| 按钮 | 条件与说明 |
| --- | --- |
| `批准` / `退回` | 需 `knowledge.review` 且 review_status = pending |
| `批准发布` / `退回修正` | 详情抽屉内 |
| `废止` / `恢复生效` | 直接执行，无二次确认 |
| `复核` / `登记复核（已到期）` | 到期时提示 |
| `移除` | 弹窗确认 |

### 4.3 党员发展 /members

**用途**：登记年度批次、材料与培养记录，**依组织决定**完成阶段人工办理；规则建议与评分只供人工核对。

**页面顶部常驻「决策边界」声明**：「阶段决定须由具备权限的组织人员依规登记。规则建议与评分不构成组织认定或选拔结论。」

**工作区页签**（按显示顺序）：`人员档案` / `组织关系接转` / `上级审批备案` / `年度批次` / `提醒待办` / `多轮选优`

#### A. 人员档案（名册）

- 页头按钮（需 `member.stage_transition` 才显示）：`登记培养对象`、`下载模板`、`导出名册`、`导入名册`、`刷新`。
- `登记培养对象` 表单：姓名*、所属组织*（下拉；若账号没有有效组织，提示"账号没有可登记的有效组织，请联系管理员绑定组织。"）、已确认的当前阶段、进入阶段日期（留空为今天）、待办数、已具备材料（每行一项）→ `保存登记`。
- `导入名册` 表单：名册文件（.xlsx）、名册来源说明（4–200 字，会写入审计记录）→ `预检（不写库）` → `确认导入 N 人`。导入报告表格列：`行 | 姓名 | 结果 | 说明`，结果取值 `可登记`/`已登记`、`已存在`、`不能导入`。
- 左侧名册为**卡片列表**（姓名 / 阶段徽标 / 在阶段 N 天 / 待办 N），非表格。
- 空态："暂无培养对象——当前组织范围内尚无台账，可由具备权限的组织人员登记。"

#### B. 档案详情（MemberFilePanel，五个页签）

`档案与材料` / `培养与评分` / `人工流转` / `办理记录` / `档案检查`

**① 人工流转（唯一能改变阶段的入口）**

1. 选中左侧名册中的对象（未选时提示"请选择一名培养对象"）。
2. 切到 `人工流转` 页签：**目标阶段下拉只给「下一阶段 + 退回」两项**；若当前是 `member` 或 `rejected` 阶段则无选项，显示"当前阶段没有可登记的后续流转。"
3. 填写：

   | 字段 | 要求 |
   | --- | --- |
   | 人工决定的目标阶段 | 下拉（下一阶段 / 退回） |
   | 组织决定日期 | 必填；min = 进入阶段日期，max = 今天 |
   | 决定依据 | 必填 |
   | 组织意见 | 选填 |
   | 确认勾选 | 必勾「我已核对材料、时限及组织决定，确认登记这次人工流转。」 |

4. 点 `登记人工决定`。同页还有 `按当前阶段同步提醒`（生成到"提醒待办"页）。

**② 培养与评分 / 资格校验**

右侧分析面板三个页签：`资格校验` / `流转建议` / `待办建议`，对应 `执行资格校验`、`生成流转建议`、`生成待办建议`。这三个按钮**只出建议，不触发任何流转**。

**③ 账号与个人提交**（折叠区）

`关联本人档案`、`下载提交原件`、`上一页材料` / `下一页材料`。无权限时提示："当前账号可查看档案；阶段决定由具备权限的组织人员登记。"

#### C. 年度批次

`建立年度批次` → 弹窗"建立年度发展批次"：批次号*、批次名称*、所属组织*、建立理由* → `保存年度批次`。

#### D. 多轮选优（投票）

1. 先建好年度批次，再回到 `多轮选优`。
2. 选择 `本年度批次` + `投票轮次`（1–20）。
3. 每行下拉 `本轮选择`：`暂不纳入` / `同意` / `不同意` / `弃权`，附 `说明`。
4. 点 `核对本轮记录（N）` → 弹窗勾选「我已逐项核对，同意提交本轮记录。提交后本账号不可重复投票。」→ `提交本轮记录`。
5. 汇总表：`培养对象 | 同意 | 不同意 | 弃权`。已投过本轮时按钮消失，提示"当前账号已提交本轮记录，可以查看汇总。"

**团组织推优**（同页）：表格第 3 列即"团组织推优"，行按钮 `登记推优` / `作废推优`；弹窗"登记团组织推优"：推荐团组织*、推荐日期*、推优说明（团组织意见，第三人信息按密级收敛）、办理依据/说明* → `登记推优记录`。无记录时提示"尚无推优记录（不阻断选优，请组织核对是否为 28 周岁以下青年）"。

**选优结论**：勾选"纳入" → 填 `拟推进阶段`（积极分子 / 发展对象 / 预备党员 / 正式党员）、`研究程序`（支委会 / 党员大会）、`研究日期`、`结论依据*` → `登记拟推荐名单（N）`。结论区行按钮：`送审`、`修订名单与依据`、`审核`、`明细与留痕`；状态徽标：`草稿 / 待审核 / 已通过 / 已退回`。

#### E. 上级审批备案

- `登记报送` → 弹窗"登记向上级党组织报送"：报送事项*、报送党员*、上级组织名称*、报送日期*、报送文号、备注、办理依据/说明* → `登记为已报送待批复`。
- 行操作 `回填批复`：选择 `同意 / 批准`、`不同意`、`需补充材料`；同意/不同意时批复文号必填，选择"需补充材料"时"还缺什么材料"必填 → `回填「同意 / 批准」`。
- 其他：`作废`、`留痕`、`导出台账`。
- **注意：系统内没有"审批通过"按钮**——审批结论以上级批复回填为准。

#### F. 组织关系接转

`登记转出`（→ 登记为待接收）、`登记转入`（→ 登记转入并生成档案清单）、`登记回执（完成转出）` / `登记回执（档案已核对）`、`作废`、`留痕`。

### 4.6 年度考核 /assessment

**用途**：按年度和组织归集已登记业务数据，核查缺项与佐证，形成可人工修订的计划草案。顶部横幅原文：「统计与计划供组织人员研究；评分与归集为辅助参考，未经人工终审不得导出或流转。」

**页签**：`指标与归集` / `年度任务` / `佐证与缺项` / `计划草案` / `提醒与设置`

#### 标准作业顺序

```
① 新增/修订指标 → ② 新增年度任务 → ③ 关联真实佐证 → ④ 重新归集
→ ⑤ 确认已核查归集 → ⑥ 归档审核后佐证目录 → ⑦ 导出材料目录
```

工具栏：`刷新状态`、`重新归集`（需至少 1 条已生效指标）、`导出材料目录`（需 `assessment.export`）。

#### ① 指标（需 `assessment.configure`，学校组织）

`新增指标` / `修订版本` → 字段：

| 字段 | 取值 |
| --- | --- |
| 指标编码* | 追加版本时只读 |
| 指标名称*、考核要求* | — |
| 数据源* | 组织建设 / 人员阶段登记 / 人员材料核验 / 组织生活 / 中心组学习 / 制度文件 / 人工特色创新 |
| 统计口径 | 去重记录次数·人数 / 实到÷应到×100 / 完整材料÷记录数×100 / 已审核人工值求和 |
| 目标值*、判定条件* | 实际值 ≥ 目标 / ≤ / = |
| 单位*、统计开始*、统计结束* | — |
| 生效时间 | 留空立即生效 |
| 阶段筛选、组织类别 | 条件显隐；组织类别多选：学校/院系/支部 |
| 制度文件编号、佐证清单 | — |
| 已取得学校指标口径确认 + 指标确认依据* | 勾选后依据必填 |

→ `保存指标版本`。空态提示："本年度暂无已生效指标；尚未导入或确认真实学校指标。"

#### ② 年度任务

`新增年度任务` → 任务名称*、关联指标*、责任用户*、任务期限*（限本年度）、人工填报进度*（0–100）；人工指标追加 `人工特色项实际值*` / `实际完成日期*` / `录入或修订依据` → `保存任务`。

行内：`修订任务`、`审核通过`（需 `assessment.review`）、`退回补充`。卡片显示 `完成/逾期/临近期限/进行中` 与 `待人工审核/人工审核通过/退回补充`。

#### ③ 佐证与缺项

`关联真实佐证` → 佐证指标*、材料类别*、已有文件编号* → `绑定材料版本`；行内 `确认佐证版本` / `退回补充`；`归档审核后佐证目录`（启用条件：存在当前归集 + 审核已通过 + 学校开启归档 + 缺项为 0）。

#### ④⑤ 归集与确认

`重新归集` → 查看缺项 → `确认已核查归集`（**有缺项时禁用**）或 `退回补充`。

#### ⑥ 计划草案

`生成计划草案`、`保存计划修订版本`、`人工确认计划` / `退回修订`。

#### ⑦ 导出

唯一入口：工具栏 `导出材料目录`，产出 `党建考核-{年}-{组织}.zip`。禁用时悬停可见原因，三条原文：

- 「尚无与当前数据一致的归集，请先重新归集。」
- 「仍有 N 项缺项，补齐后导出才是完整评价。」
- 「归集{X}，未经人工终审不得流转。」

#### 提醒与设置

`扫描提醒`、`登记处理结果`、`保存学校确认`。提醒随后端每 300 秒自动扫描一次，也可手动扫描。"当前用户暂无提醒；只有责任人可以登记处理结果。"

### 4.8 个人材料 /my-materials

**用途**：提交本人材料并查看已提交记录。

**表单**：材料标题*（≤200）、材料类型（思想汇报 / 学习心得 / 证明材料 / 其他材料）、材料说明（≤2000）、材料文件*。

**限制**：支持 `.pdf .docx .txt .md .png .jpg .jpeg`，单个文件不超过 `MAX_UPLOAD_SIZE`（默认 10 MB）；超限报"文件超过大小限制，请重新选择。"

**提交后**：提示"材料已提交，待组织核验。"，列表每条固定徽标"已提交，待组织核验"，可 `下载原件`。页面声明："提交记录不等于审核通过，不会自动修改本人阶段或组织登记的材料清单。"

列表每页 20 条，含上一页 / 下一页。空态："尚未关联本人档案——请联系组织管理员关联本人档案后提交材料。" / "暂无提交记录。"

> **隐私边界**：私有材料原件不进入知识库、不发送模型；只有本人与授权组织人员可见。

### 4.9 创建账号 /accounts

**用途**：为本单位人员开通登录账号并设置角色与组织。**仅系统管理员可见**。

**表单**（右上角徽标"仅系统管理员"）：

| 字段 | 规则 |
| --- | --- |
| 用户名 | 必填，≤50 字符，**全局唯一**，不能包含空白 |
| 姓名 | 必填，≤50 |
| 角色 | 系统管理员 / 校级管理员 / 院系管理员 / 支部书记 / 组织员 / 党员 / 申请人 |

**常见校验提示**：

- "密码长度或内容不符合要求。"

### 4.10 治理 /governance

**用途**：按当前账号授权做租户/组织/账号维护、人工审核、学校配置、任务与运行审计。路由需 `admin.review`。

**页签（按顺序）**：`组织与账号`（需 `admin.identity`）→ `人工审核`（默认）→ `学校配置`（需 `admin.config`）→ `任务台账` → `运行审计`（需 `admin.ops`）→ `问答记录`（需 `admin.audit`）

#### ① 组织与账号

- 组织目录：`管理租户` 下拉；`登记租户` / `维护租户` **仅系统管理员可见**；`新增组织`；每行 `维护`。
  - 维护组织弹窗：名称、组织类型、上级组织、保持有效。
  - 表格列：`组织 | 类型 | 上级 | 状态 | 维护`。
- 用户与角色：`新增用户` **仅系统管理员**；每行 `维护`（名称、登录账号、初始密码至少 12 字符、授权角色、所属组织、保持有效）。
  - 表格列：`用户 | 账号 | 角色 | 所属组织 | 状态 | 维护`。
- 空态："组织尚未登记，请补充学校确认的组织资料。" / "暂无符合条件的账号。"

#### ② 人工审核

- `提交审核`：业务类型、对象编号、统计年度、投票轮次。
- `查看材料`：弹窗含快照、`完整材料与依据` 折叠 JSON、`人工结论`（通过 / 退回补充）+ 必填审核意见。

  - "提交人不能自审"

  - "你是此版本提交人，须由另一位授权人员审核"

#### ③ 学校配置（需 `admin.config`）

| 配置区 | 内容 |
| --- | --- |
| 准入资料、组织资料与三方评审 | 学校基础信息 |

## 5. 业务规则速查

### 5.1 党员发展阶段与流转

```
入党申请人 → 入党积极分子 → 发展对象 → 预备党员 → 正式党员
                  ↑              ↑
                  └──── 退回 ─────┘（考察不合格/公示有异议 → 退回 → 可回到积极分子）
```

| 流转 | 最短时限 | 所需材料 |
| --- | --- | --- |
| 申请人 → 积极分子 | — | 入党申请书、党组织谈话记录 |
| 积极分子 → 发展对象 | **365 天** | 思想汇报、培养考察记录、群众评议材料、党课培训证明 |
| 发展对象 → 预备党员 | **90 天** | 政治审查材料、公示情况报告、支部大会决议、上级审批意见 |
| 预备党员 → 正式党员 | **365 天** | 转正申请书、预备期考察记录、支部大会决议 |

- 培养期上限与提醒提前量可在 `config/business_rules.yaml` 配置（当前：积极分子 365 天、发展对象 90 天、预备期 365 天、提醒提前 30 天）。
- 界面"资格校验"只做核对，**不会自动流转**；真正流转必须在 `人工流转` 页手工登记。

### 5.2 组织生活频次要求

依据《中国共产党支部工作条例（试行）》：

| 活动类型 | 周期要求 | 备注 |
| --- | --- | --- |
| 支部党员大会 | 每季度至少 1 次 | — |
| 党课 | 每季度至少 1 次 | — |
| 党支部委员会会议 | 每月至少 1 次 | — |
| 党小组会 | 每月至少 1 次 | 未划分党小组的支部不适用 |
| 组织生活会 | 每年至少 1 次 | 一般安排在第四季度 |

系统明示："频次为制度提示，完成认定以人工审核通过的会议记录为准，系统不自动认定完成。"

### 5.3 年度考核统计口径

| 数据源 | 说明 |
| --- | --- |
| 组织建设 | 组织数量与结构 |
| 人员阶段登记 | 发展阶段记录 |
| 人员材料核验 | 材料完整度 |
| 组织生活 | 已审核活动次数 |
| 中心组学习 | 已归档学习记录 |
| 制度文件 | 制度供给情况 |
| 人工特色创新 | 人工填报值 |

统计口径四种：去重记录次数·人数 / 实到÷应到×100 / 完整材料÷记录数×100 / 已审核人工值求和。判定条件：实际值 ≥ / ≤ / = 目标值。

**考核纯计算原则**：稳定来源去重、明确统计期间、零分母与缺项明确，**禁止模型下结论**；未接入的数据源不得表示为零。

### 5.4 四条"不可逾越"的边界

1. **提交人不能自审**——纪要、考核、选优、材料审核均适用。
2. **未保存不能送审/归档**——所有"生成、送审、审核、归档"按钮在有未保存改动时禁用。
3. **未经人工终审不得导出**——考核导出需归集一致 + 零缺项 + 已终审。
4. **涉密不处理**——数据分级为"涉密"时禁止在线向量化与 AI 处理。

## 6. 五条端到端主流程

### 流程一：制度入库到可问答

```
① 院系管理员登录 → /knowledge
② 上传文件（≤10MB，PDF/Word/TXT/MD）→ 填文档编号、层级、可见范围、数据分级
③ 打开详情抽屉 → 处理待检索片段（状态变"可检索"）
④ 有 knowledge.review 的人员 → 批准
⑤ 到 /ask 提问 → 检查顶部结论条为"依据充分" → 逐条点 [n] 核对来源
⑥ 依据不充分 → 补充制度文件或调整提问
```

### 流程二：发展一名党员（从申请到转正）

```
① 支部书记 → /members → 人员档案 → 登记培养对象（阶段=入党申请人）
② 收齐材料 → 档案与材料页登记已具备材料
③ 人工流转页 → 目标阶段=入党积极分子 → 填组织决定日期/依据 → 登记人工决定
④ 满 365 天 → 重复 ②③（发展对象需满 365 天、预备党员需满 90 天前置）
⑤ 年度批次 → 建立年度批次 → 多轮选优 → 逐轮投票（每账号每轮一次）
⑥ 团组织推优（28 周岁以下青年）→ 登记推优
⑦ 选优结论 → 登记拟推荐名单 → 送审 → 他人审核
⑧ 上级审批备案 → 登记报送 → 收到批复后回填批复
⑨ 预备期满 365 天 → 人工流转到正式党员
```

### 流程三：一次支部大会的完整闭环

```
① /meeting → 登记活动计划（类型=支部大会）
② 活动资料 → 添加参会人员 → 从知识库选择参考资料 → 保存活动资料
③ 议程与纪要 → 生成议程与通知草稿 → 从原文提取纪要 → 保存
④ 提交纪要审核 → 由另一位有审核权限的人员：人工审核纪要
⑤ 活动任务 → 从原文登记任务 → 确认责任与期限 → 登记落实结果
⑥ 版本与归档 → 归档已审核纪要 → 导出归档记录
```

### 流程四：一次中心组学习

```
① /study → 新建年度计划 → 保存年度草案
② 增加学习安排 → 提交计划审核 → 他人通过计划审核
③ 每期：推荐学习材料 → 保存本期安排与提纲 → 登记学习活动
④ 录入参学人员、原始学习文本 → 从已保存原文生成纪要 → 保存学习记录与纪要
⑤ 提交纪要审核 → 他人通过纪要审核
⑥ 学校配置里确认电子记录效力 → 归档已审核记录 → 导出学习材料
```

### 流程五：年度考核

```
① 学校管理员 → /assessment → 指标与归集 → 新增指标（数据源/口径/目标值/判定条件）
② 年度任务 → 新增年度任务（绑定指标、责任人、期限）→ 审核通过
③ 佐证与缺项 → 关联真实佐证（绑定已有文件编号）→ 确认佐证版本
④ 重新归集 → 查看缺项 → 补齐后确认已核查归集
⑤ 佐证页 → 归档审核后佐证目录
⑥ 计划草案 → 生成计划草案 → 人工确认计划
⑦ 导出材料目录 → 党建考核-{年}-{组织}.zip
```

## 7. 常见问题与排障

### 7.1 登录与权限

| 现象 | 原因与处理 |
| --- | --- |
| 登录失败 | 确认账号已开户且在有效租户/组织内；系统无默认密码；遗忘请平台管理员在治理页「维护」重置 |
| 看不到某个菜单 | 角色缺对应权限码；到 `/system` 查看自己的权限码清单 |
| 提示"权限不足（40301）" | 该操作需要更高角色；记录 trace_id 交管理员核对 |
| 提示"数据范围校验未通过" | 账号所属组织无权访问该数据，换有范围的组织账号 |
| 落到"无法访问该页面" | 联系平台系统管理员核对**角色与所属组织** |

### 7.2 知识库与问答

| 现象 | 原因与处理 |
| --- | --- |
| 上传被拒 | 超过 10 MB 或格式不在支持列表；扫描件/照片没有文字层，系统读不出正文 |
| 状态一直"待处理" | 到详情抽屉点「处理待检索片段」；失败时按钮变「重试处理」，失败原因会直接显示 |
| 涉密文件无法处理 | 设计如此：涉密资料不提供在线向量处理 |
| 检索不到刚上传的文件 | 确认已完成向量化（状态=可检索）、可见范围与你的角色匹配、文件在有效期内 |
| 答非所问 / 依据不充分 | 知识库缺少对应制度文件，先补文件；或换更具体的提问 |
| 想改文档编号 | 不可改：文档编号入库后不可修改 |

### 7.3 党员发展

| 现象 | 原因与处理 |
| --- | --- |
| "账号没有可登记的有效组织" | 账号未绑定组织，请管理员在治理页维护 |
| 人工流转下拉没有选项 | 当前阶段已是「正式党员」或「退回」，没有可登记的后续流转 |
| 流转时提示时限不足 | 未满足最短培养期（365/90/365 天）；先核对进入阶段日期 |
| 投票按钮消失 | 本轮已投过（每账号每轮一次），只能查看汇总 |
| 找不到"审批通过"按钮 | 设计如此：结论以上级批复回填为准，用「回填批复」 |
| 党员看不到本人档案 | 组织人员尚未在名册中关联本人档案；系统不按姓名自动匹配 |

### 7.4 组织生活 / 学习 / 考核

| 现象 | 原因与处理 |
| --- | --- |
| "须由另一位有审核权限的人员审核" | 提交人不能自审，换其他授权人员操作 |
| 审核/归档按钮禁用 | 有未保存改动 → 先保存；或状态不满足（待审/已通过/已归档） |
| 学习归档不可用 | 学校尚未确认电子记录效力，先到学校配置登记或到学习页底部确认 |
| 考核"重新归集"禁用 | 本年度还没有已生效指标，先登记指标 |
| 导出按钮禁用 | 悬停看原因：未归集 / 有缺项 / 未终审 |
| 民主评议列表为空 | 账号可访问范围内没有支部，或在册正式/预备党员为 0 |

### 7.5 系统层面

| 现象 | 原因与处理 |
| --- | --- |
| 页面打不开 | 检查服务器 80 端口与容器状态；见 [9.3 运维命令速查](#93-运维命令速查) |
| `/api/*` 报 502 | 后端容器未就绪；看日志 `docker compose logs -f app` |
| 系统页显示"需要迁移" | 执行 `alembic upgrade head` |
| "模型连通性：未验证" | 15 分钟内无成功调用即显示，**不影响使用**；做一次问答即可 |
| 提问很慢 | 首次模型调用较慢；高峰可错峰批量向量化 |

## 8. 安全与合规边界

- **AI 只做辅助**：阶段认定、考核结论、选优名单、归档效力一律人工决定并留痕。
- **数据分级管控**：公开 / 内部 / 敏感 / 涉密四级，分级只能提高不能降低；敏感与涉密不送云端模型。
- **出网白名单**：仅放行获准的云端服务（当前为阿里云百炼），由治理页"模型使用范围"控制。
- **私有材料隔离**：个人材料原件不进知识库、不送模型，仅本人与授权组织人员可见。
- **提交人不能自审**：所有审核类动作强制换人。
- **全量审计**：登录、读取、提交、审核、导出、配置变更全部写入审计日志，可查询导出。
- **令牌时效**：访问令牌 30 分钟、刷新令牌 7 天，支持吊销。
- **演示数据**：预置的学校、组织、名册、制度文档均为「未核验演示」，正式使用前必须由校方核对替换。
