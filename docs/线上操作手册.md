## 2. 系统是什么

### 2.1 部署架构（单机四容器）

```
浏览器 → http://129.204.32.148:80
            ↓
       Nginx 容器（party-agent-frontend）  SPA 静态资源
            ↓ /api/*
       FastAPI 容器（party-agent-app）:8000
            ├─ PostgreSQL + pgvector（party-agent-postgres）:5432
            └─ Redis（party-agent-redis）:6379
            ↓（出网白名单）
       阿里云百炼：qwen3.8-flash / text-embedding-flash / text-rerank
```

数据卷：`party-agent-server_postgres_data`、`_redis_data`、`_originals`（上传原件）、`_audit_spool`（审计留痕）。容器 `restart: unless-stopped`，服务器重启后自动拉起。

### 2.2 功能模块与入口

| 模块 | 路径 | 说明 |
| --- | --- | --- |
| 制度问答 | `/ask` | 基于知识库检索作答，带引用来源；无依据时明确拒答 |
| 知识库 | `/knowledge` | 制度文件上传、切分、向量化、检索；基层角色只读目录 |
| 党员发展 | `/members` | 名册、材料、批次、阶段流转、会议投票、上报 |
| 中心组学习 | `/study` | 年度学习计划、条目、纪要审核与归档 |
| 年度考核 | `/assessment` | 指标登记 → 任务分解 → 佐证绑定 → 归集导出 |
| 组织生活 | `/meeting` | 三会一课、主题党日等任务台账 |
| 本人档案 | `/my-archive` | 党员/申请人只读查看本人档案 |
| 个人材料 | `/my-materials` | 提交私有材料原件（不进知识库、不送模型） |
| 系统管理 | `/accounts` `/governance` `/system` | 开户、租户组织治理、运行与就绪详情 |

## 3. 首次上线四步初始化

> 若平台管理员已存在（当前 `admin` 已开户），直接从第 2 步开始。

### 3.1 第 1 步：开平台管理员账号

服务器终端执行（只需一次，脚本幂等）：

```bash
cd /opt/dangjian-agent
docker compose -f docker-compose.server.yml exec -T app \
  python scripts/server_init_admin.py --username admin --password '<强密码≥8位>'
```

- 输出 `[ok] user created: admin` 即成功；已存在时输出 `[skip]`。
- 忘记密码时加 `--reset-password` 重置（不改动其他数据）。
- 脚本只在 `ENV=development/testing` 下运行，不改环境变量即可。

### 3.2 第 2 步：登记租户与组织树

用 `admin` 登录 → 进入 `/governance`（治理）：

1. **租户**：新增学校租户（如「湖南科技职业技术学院」），类型 school。
2. **组织树**（自顶向下建，顺序不能颠倒）：

   ```
   湖南科技职业技术学院党委（school，无父级）
     ├─ 信息工程学院党总支（department，父级 = 学校）
     │    ├─ 教工第一党支部（branch，父级 = 院系或学校）
     │    └─ 学生第一党支部
     └─ 机电工程学院党总支
   ```

硬规则（服务端强制校验）：同租户只能有一个 school 根组织；school 不能有父级；department 父级必须是 school；branch 父级是 school 或 department。违反规则会返回 422，页面给出提示。

批量导入可改用脚本：

```bash
# 按配置清单导入（默认 --manifest config/module6-school.pending.json，默认只校验不加 --apply）
docker compose -f docker-compose.server.yml exec -T app \
  python scripts/module6_bootstrap.py --manifest config/module6-school.pending.json --apply
```

### 3.3 第 3 步：开业务账号

`/accounts`（创建账号）或治理页「账号」页签：

| 字段 | 要求 |
| --- | --- |
| 用户名 | 全局唯一，重复返回冲突 |
| 密码 | ≥8 字符、≤72 个 UTF-8 字节；**系统不返回明文，创建后请当面告知本人** |
| 角色 + 组织 | 学校/院系管理员绑定学校/院系；支部书记、组织员、党员、申请人绑定支部 |

学校/院系管理员只能维护本范围的组织与既有账号；**新增账号与登记租户仅限平台管理员**，界面也不对其他角色显示。

### 3.4 第 4 步：装知识、试问答

1. 用院系管理员及以上账号（需 `knowledge.manage`）进入 `/knowledge` → 上传制度文件（PDF/DOCX/TXT/MD/PNG/JPG，默认 ≤10MB）。
2. 打开文档详情面板，状态为「待处理/部分可检索」时点**处理待检索片段**触发向量化（调用云端 Embedding，**会产生费用**）。
3. 到 `/ask` 提问，验证回答带引用角标、可溯源。
4. `/system` 查看依赖与模型就绪详情（仅平台管理员）。

### 3.5 上线后必须处理的三件事

| 事项 | 操作 |
| --- | --- |
| 改掉初始口令 | 全部 8 个预置账号的口令在开户时设定，正式交付前逐一修改并分发 |
| 清理重复租户 | 两条同名「湖南科技职业技术学院」租户，保留有账号与组织树的那一条（`d5584666…`），另一条（`e410e3b3…`，仅一个孤立 school 组织）确认无用后在治理页停用 |
| 替换演示数据 | 7 篇制度文档、6 条名册均为演示/未核验资料，需替换为校方权威文件并人工核对 |

## 4. 角色与权限

| 角色 | 权限范围 | 主要入口 |
| --- | --- | --- |
| system_admin 平台管理员 | 全平台；开户、租户/组织治理、系统详情 | `/accounts` `/governance` `/system` |
| school_admin 学校管理员 | 全校业务 | `/members` `/study` `/assessment` `/meeting` `/knowledge` |
| department_admin 院系管理员 | 本院系 | 同上（范围限定） |
| branch_secretary 支部书记 | 本支部 | 同上（无中心组学习） |
| organizer 组织员 | 本支部协助 | 同支部书记 |
| member 党员 | 本人数据 + 制度目录 | `/my-archive` `/my-materials` `/ask` `/knowledge` |
| applicant 申请人 | 同党员（制度目录仅公开范围） | 同上 |

权限边界 = **角色 × 所属组织**共同决定；知识库维护需 `knowledge.manage`（院系管理员及以上），基层角色只读。

## 5. 各角色日常操作

### 5.1 平台管理员

| 操作 | 步骤 |
| --- | --- |
| 开户 | `/accounts`：填用户名、姓名、角色、组织、密码 → 提交 |
| 停用/启用账号、改组织归属 | `/governance` → 账号 → 编辑（PATCH `/api/v1/admin/users/{id}`） |
| 登记/停用租户与组织 | `/governance` → 租户 / 组织 |
| 业务配置 | `/governance` → 配置（培养期上限、考核周期等），每次修改进配置历史与审计 |
| 人工审核 | `/governance` → 审核：对待定事项作出通过/驳回决定 |
| 运维治理 | 渠道清单、事件路由、投递台账、发起渠道自检（需 `config.manage`） |
| 系统详情 | `/system`；接口 `/api/v1/admin/health`、`/api/v1/admin/health/ready` |

> 公开探针 `/api/v1/health/*` 只返回整体状态；**详细依赖与模型信息仅平台管理员可见**，校级/院系管理员也看不到。

### 5.2 学校 / 院系管理员

**党员发展 `/members`**

1. 名册：查看本范围培养对象；新增时填写真实人员信息（不按姓名自动推断）。
2. 材料：登记各阶段组织材料。
3. 阶段流转：**由组织人员人工完成** 申请人 → 积极分子 → 发展对象 → 预备党员 → 正式党员；系统辅助结果不构成组织认定。
4. 批次与投票：按年度/批次管理；支部会议投票留痕。
5. 培养期上限：积极分子/预备党员各 365 天（可配置），超期生成提醒。

**中心组学习 `/study`**

- 建年度学习计划与条目 → 登记共用活动 → 上传会议纪要。
- 纪要须**由另一位组织人员审核**后归档；电子归档默认关闭，学校确认效力后由校级/系统管理员登记依据。

**年度考核 `/assessment`**

- 顺序：学校管理员登记年度指标 → 院系/支部制定任务 → 绑定佐证 → 归集导出。
- 站内提醒随后端每 300 秒自动扫描一次（`ASSESSMENT_REMINDER_SCAN_SECONDS`），也可在工作台手动扫描。
- **没有指标时系统不会导入示例指标**，需人工登记。

**组织生活 `/meeting`**：登记三会一课、主题党日等任务与台账。

**知识库 `/knowledge`**：上传 → 切分 → 向量化；可下载原件（含历史版本）、查看处理状态与失败原因、修正元数据。

### 5.3 支部书记 / 组织员

- 本支部范围内的名册、材料、投票、组织生活。
- 无中心组学习入口。
- 党员账号开通后，需在名册中**明确关联本人档案**（选择正确台账，不按姓名推断、不覆盖他人既有关系），否则党员看不到本人档案。

### 5.4 普通党员 / 申请人

| 功能 | 说明 |
| --- | --- |
| `/my-archive` | 只读本人档案（需组织人员先关联） |
| `/my-materials` | 提交私有材料：标题、类型、说明 + 原件，≤10MB；重复提交不会重复保存；可下载本人原件；**不进知识库、不送模型** |
| `/ask` | 制度问答，带引用；无依据时明确提示不编造；「最近提问」按本人账号隔离，可逐条删除 |
| `/knowledge` | 只读查阅授权范围内制度目录与摘要，可下载制度原件；无上传/废止权限 |

## 6. 四条核心业务流程

```
① 制度入库：上传文件 → 切分 → 向量化（云端 Embedding）→ 可见范围分级（公开/学校/院系/支部）
② 智能问答：提问 → 混合检索 + 重排 → 带引用作答 → 无依据则拒答（不编造）→ 人工确认
③ 党员发展：名册登记 → 材料归集 → 人工阶段流转 → 支部投票 → 上报 → 提醒与超期预警
④ 年度考核：指标登记 → 任务分解 → 佐证绑定 → 归集 → 提醒 → 导出
```

> 所有 AI 结论均为辅助参考，关键业务动作（阶段认定、归档、考核结论）一律由组织人员人工完成并留痕。

## 7. 运维手册

所有命令在服务器 `/opt/dangjian-agent` 目录执行（为简洁，下文用 `dc` 代指 `docker compose -f docker-compose.server.yml`）。

### 7.1 日常巡检

```bash
cd /opt/dangjian-agent
docker compose -f docker-compose.server.yml ps          # 四容器应为 Up
curl http://127.0.0.1/api/v1/health/live                # 进程存活
curl http://127.0.0.1/api/v1/health/ready               # 200 = 依赖、表结构、模型注册均正常
docker stats --no-stream                                # CPU / 内存（4核3.6G，关注 app 与 postgres）
docker compose -f docker-compose.server.yml logs --tail=100 app   # 最近日志
```

建议每日一次 `ready` 检查；`logs` 为 JSON 格式，可按 `trace_id` 追踪单次请求。

### 7.2 启停与重启

```bash
docker compose -f docker-compose.server.yml restart app          # 只重启后端（不影响数据）
docker compose -f docker-compose.server.yml restart frontend     # 只重启前端
docker compose -f docker-compose.server.yml down                 # 停止并移除容器，数据卷保留
docker compose -f docker-compose.server.yml up -d                # 重新启动
```

`down` 不会删除数据卷，业务数据不丢。

### 7.3 备份（每天一次，建议加 crontab）

**数据库**——用 postgres 容器自带的 pg_dump（app 容器内没有 pg_dump）：

```bash
mkdir -p /root/backups
docker exec party-agent-postgres pg_dump -U party_user -d party_agent -Fc \
  > /root/backups/pg_$(date +%F).dump
```

**上传原件与审计留痕**（数据卷）：

```bash
docker run --rm -v party-agent-server_originals:/data -v /root/backups:/out \
  alpine tar czf /out/uploads_$(date +%F).tar.gz -C /data .
docker run --rm -v party-agent-server_audit_spool:/data -v /root/backups:/out \
  alpine tar czf /out/audit_$(date +%F).tar.gz -C /data .
```

**配置文件**：把 `/opt/dangjian-agent/.env` 单独加密保存一份（内含 SECRET_KEY、百炼 Key、数据库口令），与备份包分开放。

**保留策略**：建议本地留 7 天、异地留 30 天；每季度做一次恢复演练，确认备份可用。

应用内另有加密备份脚本（产出加密 zip，恢复需同一套密钥与 `.env`）：

```bash
docker compose -f docker-compose.server.yml exec -T app \
  python scripts/module6_backup.py backup --output /app/uploads/backup_$(date +%F).zip
```

### 7.4 恢复（简要）

```bash
# 1) 停业务，避免写入
docker compose -f docker-compose.server.yml stop app
# 2) 建空库后恢复（或先drop再create，操作前务必确认已备份当前数据）
docker exec -i party-agent-postgres pg_restore -U party_user -d party_agent --clean --if-exists \
  < /root/backups/pg_2026-10-17.dump
# 3) 还原文件卷
docker run --rm -v party-agent-server_originals:/data -v /root/backups:/in \
  alpine tar xzf /in/uploads_2026-10-17.tar.gz -C /data
# 4) 起服务并检查
docker compose -f docker-compose.server.yml up -d
curl http://127.0.0.1/api/v1/health/ready
```

### 7.5 更换百炼 API Key

```bash
cd /opt/dangjian-agent
sed -i 's|^DASHSCOPE_API_KEY=.*|DASHSCOPE_API_KEY=sk-新的Key|' .env
docker compose -f docker-compose.server.yml up -d app
curl http://127.0.0.1/api/v1/health/ready     # 确认为 200
```

模型名在 `.env` 中：`CHAT_MODEL=qwen3.8-flash`、`EMBED_MODEL=qwen3.7-text-embedding-flash`、`RERANK_MODEL=qwen3.7-text-rerank`（均已实测可用）。

### 7.6 版本更新（发布新代码）

```bash
cd /opt/dangjian-agent
# 1) 备份（见 7.3）
# 2) 更新代码：git pull，或用本机打包上传替换
# 3) 重新构建并启动（镜像源已在 .env 的 DOCKERHUB_MIRROR 配好）
docker compose -f docker-compose.server.yml up -d --build
# 4) 执行数据库迁移
docker compose -f docker-compose.server.yml exec -T app python -m alembic upgrade head
# 5) 验证
curl http://127.0.0.1/api/v1/health/ready
docker compose -f docker-compose.server.yml ps
```

迁移头当前为 `022_member_vote_dedup_batch`。**迁移前必须备份**；不要对业务库执行 `alembic stamp head` 或删表脚本。

### 7.7 关于 HTTPS 与生产化

当前是 HTTP 明文，仅适合验证与内网使用。正式对外务必：

1. 申请域名与证书，改用 `config/nginx-production.conf`，放行防火墙 TCP 443；
2. 改 `.env` 的 `ENV=production` 前**先配好 PostgreSQL/Redis 的 TLS**——production 会强制校验，未配 TLS 会直接启动失败；
3. 收紧 `ALLOWED_HOSTS`、`SECRET_KEY` 轮换策略与密钥保管。

## 8. 常见问题排障

| 现象 | 原因与处理 |
| --- | --- |
| 打不开页面 | 检查轻量服务器防火墙是否放行 80；`docker compose ps` 看 frontend 是否 Up；`curl http://127.0.0.1` 看本机是否 200 |
| `/api/*` 报 502 | app 容器未就绪：`docker compose ps` + `logs -f app`；确认 `ready` 返回 200 |
| `ready` 返回 503 | 数据库/Redis/表结构/模型注册之一缺失；平台管理员登录 `/system` 或请求 `/api/v1/admin/health/ready` 看明细 |
| 「模型服务未就绪 / 依赖服务暂不可用」 | 检查 `.env` 的 `DASHSCOPE_API_KEY` 是否有效、余额是否充足；换 Key 后 `up -d app` |
| 「模型连通性：未验证」 | 观察项 `model_warm`，15 分钟内无成功调用即显示未验证，**不影响使用**；做一次正常问答即转为已验证 |
| 「培养对象不存在或无权访问」 | 账号所属组织不对：平台账号没有业务数据，请用学校/院系/支部账号 |
| 登录失败 | 账号需已开户且在有效租户/组织内；系统无默认密码；遗忘用 `server_init_admin.py --reset-password` 重置 |
| 上传后检索不到 | 文档处理状态为「待处理/部分可检索」：到详情面板点「处理待检索片段」重新向量化，失败原因会直接显示 |
| 提问很慢或超时 | 首次模型调用较慢属正常；`logs -f app` 看模型返回耗时；高峰可错峰批量向量化 |
| 磁盘告警（40G） | 清理旧备份与 `/var/lib/docker` 悬空镜像：`docker image prune -a`；保留策略见 7.3 |
| 排障误判陷阱 | **不要用 `docker compose exec app python` 直接调内部就绪函数**——该进程不执行 FastAPI lifespan，会误报 `redis=unhealthy`、`models=missing`。一切以 `curl .../health/ready` 为准 |

## 9. 安全与使用边界

- **数据出网受白名单管控**：`ALLOWED_EXTERNAL_MODELS` 仅放行 `dashscope.aliyuncs.com`；涉密与敏感内容禁止提交云端处理。
- **私有材料隔离**：个人材料原件不进知识库、不送模型。
- **审计留痕**：登录、名册读取、材料提交、治理操作、配置变更全部写审计日志（`audit_logs`），留痕不可篡改。
- **会话**：访问令牌 30 分钟、刷新令牌 7 天，支持吊销。
- **人工兜底**：AI 只做辅助，任何组织认定、阶段变更、考核结论由人完成。
- **演示数据**：预置的学校、组织、名册、制度文档均标注「未核验演示」，正式使用前必须替换为校方权威资料。

## 10. 附录：命令速查卡

```bash
# === 服务状态 ===
cd /opt/dangjian-agent
docker compose -f docker-compose.server.yml ps
curl http://127.0.0.1/api/v1/health/ready
docker compose -f docker-compose.server.yml logs -f app

# === 开户 / 改密 ===
docker compose -f docker-compose.server.yml exec -T app \
  python scripts/server_init_admin.py --username admin --password '<新密码>' --reset-password

# === 迁移 ===
docker compose -f docker-compose.server.yml exec -T app python -m alembic upgrade head
docker compose -f docker-compose.server.yml exec -T app python -m alembic current

# === 备份 ===
docker exec party-agent-postgres pg_dump -U party_user -d party_agent -Fc > /root/backups/pg_$(date +%F).dump

# === 换模型 Key ===
sed -i 's|^DASHSCOPE_API_KEY=.*|DASHSCOPE_API_KEY=sk-xxx|' .env && \
docker compose -f docker-compose.server.yml up -d app

# === 更新发布 ===
docker compose -f docker-compose.server.yml up -d --build
docker compose -f docker-compose.server.yml exec -T app python -m alembic upgrade head
```
