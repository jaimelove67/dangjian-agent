## 已确认的模型与分级方案

用户指定的三个模型均已接入云端，运行时以根目录 `.env` 为准：

```dotenv
CHAT_MODEL=qwen3.8-flash
EMBED_MODEL=qwen3.7-text-embedding-flash
RERANK_MODEL=qwen3.7-text-rerank
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com
ALLOWED_EXTERNAL_MODELS=["dashscope.aliyuncs.com"]
ENABLE_DATA_LEVEL_GATEWAY=true
```

已检测并验证本地 `.env` 的云端密钥有效；密钥、数据库及 Redis 连接秘密不写入报告。无需配置本地模型目录或下载权重，生产 Compose 不再启动旧本地向量服务。

适配器使用聊天兼容接口、向量兼容接口和原生重排接口；向量固定为数据库要求的 1024 维，按最多 20 条分批，校验数量、索引、有限数值与维度。重排校验索引范围、重复结果与分数范围，HTTP 错误不返回上游正文或密钥。接口依据为 [聊天模型文档](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[向量模型文档](https://help.aliyun.com/zh/model-studio/qwen3-7-text-embedding-flash)、[同步向量接口](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api) 和 [重排接口](https://help.aliyun.com/zh/model-studio/text-rerank-api)。

若控制台提供业务空间专属 API Host，应同时修改 `DASHSCOPE_BASE_URL` 和白名单中的完整主机名。当前配置下已确认三个模型的实际成功调用；其他区域、业务空间、长期额度及生产部署未验收。就绪接口检查模型注册状态，真实调用由独立探针和页面联调验证，不在健康检查中自动产生模型请求。

实际调用还复现并修复两处响应兼容问题：聊天用量中的嵌套缓存统计原先引起响应校验失败；该向量模型本次批量响应重复返回 `index=0`，原先不能安全关联输入。现在保留嵌套用量，遇到该模型的重复零索引时逐条重试并保留输入顺序，每批最多并发 4 个请求；失败或超时取消未完成请求并阻止排队请求继续启动。其他错误索引、数量、维度或非有限向量仍被拒绝。重试会增加请求数量，大批量入库性能待测。

按用户确认的政策，**角色决定资料访问范围，问题和实际使用的文档决定模型调用等级**：

| 内容等级 | 当前处理 |
| --- | --- |
| 普通未声明问题 | 保守按内部级；客户端选择公开不能将它降级 |
| 公开及获准的内部内容 | 可以使用配置的云端模型；内部级要求精确主机白名单 |
| 敏感内容 | 在向量化、重排或生成前阻止云端发送 |
| 涉密内容 | 禁止 AI 处理，不写入检索片段 |

服务端检查声明密级、正文以及实际发送的完整提示词，包括标题、发文单位、文号和条款。身份证、手机号、邮箱及明确密级标记会提高内容等级；低级别标注的此类新文件被拒绝入库。历史脏数据在发送前再次检查。这些基础规则不能替代组织对材料的完整保密审查。
