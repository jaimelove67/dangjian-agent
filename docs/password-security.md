# 改密、审批与登录会话

2026-10-24 已补齐真实后端和当前 React 的改密闭环。支部书记、组织员、党员和申请人从头像菜单办理本人改密；平台、学校及院系管理员没有本人自主改密入口。每账号累计一次直接自主修改，以后每次均须提交原因，由平台管理员批准或驳回，每次批准只允许一次成功修改。

演示状态按租户和账号保存，密码校验使用独立随机盐的 PBKDF2-SHA256；明文密码不进入浏览器持久化、申请或审计。失败不消耗次数或授权，管理员恢复密码保留累计次数；成功改密后旧演示会话失效。这些浏览器状态仅用于演示，不能成为真实账号的权限依据。

真实模式通过 `account-security-api.js` 调用服务端，不读取演示次数或申请作为权限依据。迁移 `028_account_security` 新增实际登录会话、改密申请及累计成功改密台账，不回填虚构使用记录。

2026-10-24 联调补齐了管理员账号编辑后的真实会话失效：登录和刷新签发的会话绑定服务端账号状态，账号修改后旧访问令牌和刷新令牌均被拒绝。绑定值采用服务端 HMAC，不输出密码哈希，也不新增数据库字段。停用后重新启用不会恢复旧会话；本人在真实模式编辑账号后回到登录页。带会话号但尚未绑定账号状态的旧版令牌需要重新登录。管理员维护接口不再允许移除租户最后一位有效管理员，也不允许本人账号先于关联档案迁移组织。

访问和刷新还会验证持久会话号未撤销、未删除、未到期。平台或本校身份管理员可读取最近 500 条真实会话并撤销指定会话，保留该账号的其他有效会话。当前会话由头像菜单退出。

## 已接入的服务端契约

接口均附加 `/api/v1`。本人接口从当前身份取得账号与租户，不接受客户端指定其他对象。

| 接口 | 行为 |
| --- | --- |
| `GET /auth/password-state` | 本人累计使用状态、申请历史及一次批准授权 |
| `POST /auth/password-change` | 接收 `current`、`password`、`confirmation`，原子校验并修改 |
| `POST /auth/password-requests` | 接收原因，禁止重复待审或重复未消费授权 |
| `GET /admin/password-requests?tenant_id=...` | 平台读取管理租户的真实申请 |
| `POST /admin/password-requests/{id}/review?tenant_id=...` | 平台提交 `decision`、`comment`、`version`，拒绝过期审批版本 |
| `GET /admin/login-sessions?tenant_id=...` | 按平台/本校身份管理范围读取实际会话 |
| `POST /admin/login-sessions/{id}/revoke?tenant_id=...` | 撤销指定会话，不能在此撤销当前会话 |

服务端执行下列约束：

- 返回本人累计成功改密次数、待处理申请及尚未消费的批准授权，不由客户端传入目标账号或租户。
- 本人改密原子校验当前密码、角色、次数或一次授权，成功时更新密码并消费对应授权，失败时不扣次数；并发请求只能成功消费一次。
- 申请保存原因和处理状态，禁止重复待审批或重复有效授权；平台审批校验真实平台身份、所属租户范围及当前版本，保留审批人、意见和时间。
- 管理员恢复密码保留累计次数，明确撤销未完成申请和既有授权；当前账号及最后一位有效管理员的保护继续由后端执行。
- 所有成功改密或恢复操作使旧会话失效，并记录不含密码、校验值或令牌的审计事件；重试不得重复消费授权。

自主改密、提交申请、审批和管理员维护均在数据库事务中锁定目标账号。真实 HTTP/ORM 回归覆盖错误密码、一次成功、再次申请、非平台审批拒绝、版本冲突、管理员重置后次数保留、跨校会话拒绝及旧访问/刷新失效。独立 PostgreSQL 并发测试验证首次机会及批准授权均只能成功消费一次，浏览器验证头像改密、平台批准和单会话撤销。管理员编辑与自主改密分别执行，不能用账号 PATCH 代替自主次数和审批校验。

正式环境仍需实际数据库、Redis、认证密钥与迁移；本轮没有部署或修改正式账号。执行证据见 [前后端联调报告](integration-check-2026-10-24.md)。
