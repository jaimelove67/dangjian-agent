## 前端登录报「请求失败（HTTP 502）」= VITE_API_TARGET 写成了 localhost

- 现象：直连 `127.0.0.1:18000/api/v1/health` 是 200，走前端 `127.0.0.1:5666/api/health` 全是 502，登录页弹「请求失败（HTTP 502）」。
- 真因：`vite.config.ts` 的 proxy target 取 `VITE_API_TARGET`，写成 `http://localhost:18000` 时，Node 18+ 会优先解析成 IPv6 `::1`，而后端 `--host 127.0.0.1` 只监听 IPv4 → 代理连不上。
- 处置：`VITE_API_TARGET=http://127.0.0.1:18000` 重启前端即恢复；`tmp/local-start.sh` 已改成 127.0.0.1，并新增 `--restart`（ctypes 杀 18000/5666 再起）与「fe 5666(代理)」状态检查。
- 另：前端以 `/api` 为基准书写路径，代理会把 `/api` 重写成 `/api/v1`，所以**测代理时用 `/api/health`，不要用 `/api/v1/health`**（会变成 `/api/v1/v1/health` → 404）。

## 三条变动路径实测结论（2026-10-23，均用真实接口跑过）

| 路径 | 结果 |
|---|---|
| 只换职务 `PATCH /admin/org-leaders/{id} {title}` | ✅ 组织现状职务同步更新，姓名不动 |
| 同组织换人（离任 + 新增一届 primary） | ✅ 离任后组织现任清空，接任后自动切换，他人 primary 自动置否 |
| 校内调动 `POST /member-full/transfers {direction:in, profile_id, org_unit_id}` | ⚠️ 档案组织能改过去，但下面三处不闭环 |

**实测发现的问题（未修，待定优先级）**
1. **接转不联动组织负责人**：李国华转入校党委后，`member_profiles.org_name` 已变，但「计算机学院党委」的现任仍是"李国华 党总支书记"，系统零提示。必须人工去治理页登记离任，漏了就是"已转出的人还挂着书记"。
2. **作废转入不回滚档案组织（真 bug）**：`member_transfer_service.revoke()` 只把 `status=revoked` 并重算 relation 状态，**不还原 `profile.org_unit_id/org_name`**，但返回文案说"视同未发生"。要修得给 `member_transfers` 加 `origin_org_unit_id`（迁移 028），`_create_in` 时记下、`revoke` 时还原。
3. **一次调动要操作 3 处**（接转 → 原组织离任 → 新组织任职），无引导、无一致性校验。
4. 观察项：转入允许把党员落进 `school` 级组织（实测成功转入"测试大学党委"），党员组织关系通常应落支部，可考虑限制接收组织类型。

**恢复数据的手工要点**：直接 SQL 改 `org_leader_terms` 后 `org_units` 的现任快照**不会自动跟着变**（同步只在服务层 `sync_primary_leader` 里做）。重算：
```sql
update org_units o set leader_name=t.name, leader_title=t.title, leader_phone=t.phone
from org_leader_terms t where t.org_unit_id=o.id and t.is_primary and t.ended_on is null and not t.is_deleted;
update org_units o set leader_name=null, leader_title=null, leader_phone=null
where not exists (select 1 from org_leader_terms t where t.org_unit_id=o.id and t.is_primary and t.ended_on is null and not t.is_deleted);
```
